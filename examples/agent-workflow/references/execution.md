# 実行の共通手順

Axonの判断・操作は`axon:conventions`と`axon:work-state`、結果と申し送りの記録は`axon-kit:add-note`を使う。必要なpluginがなければ変更前に導入を案内する。

## 開始と継続

対象repository、利用先の指示、gitのbranch・HEAD・作業中の差分を確認する。既存の変更を保持し、他の作業者との未調整の同時更新や分離できない差分があれば、変更前に解消する。

`InProgress`のIssueは、今回の実行で開始したか、ユーザーまたは呼び出し元から前の作業者が終了したことと継続の指示が確認できる場合だけ再開する。

## 検証とcommit

変更に必要なテストと完了条件の確認を行う。このサンプルは独立レビューや終了監査を必須工程にしない。利用先が要求するレビューや検証は完了前に行う。

既定では、各Issueの実装と完了記録をまとめてcommitする。ユーザーの「commitしない」などの指示と、利用先のbranch・commit規約を優先し、Group配下にも引き継ぐ。

commit前に差分とstage済みの内容を確認し、対象の変更だけを含める。Git管理された`.axon/`の対象記録も含め、空commitは作らない。メッセージは変更の目的が単独で伝わる内容にする。push・PR作成はこのworkflowに含まない。

commitやhookの失敗を無視せず、原因を解消して再検証する。解消できなければ次のIssueへ進まず、未commitの変更とAxonの状態を報告する。`axon complete`済みでも自動で巻き戻さない。

## 中断

ユーザー判断を待つ間は状態を維持し、保留・引継ぎでは作業・検証の現在地と残作業をNoteに記録して、着手中のIssueを`axon:work-state`で`axon release`する。
