# 候補一覧と外部条件

この文書は、`axon tasks` の一覧の行と状況、詰まっている Group の理由、`axon proposals`・`axon tasks`・`axon show` が再浮上条件を評価する範囲と失敗の扱い、再浮上条件を実行してよいかを決める条件の許可、および再浮上条件の外部コマンドの実行契約を定める。候補集合そのものの定義は [lifecycleと構造の契約](lifecycle.md#候補集合)、状況や待ち理由の表記は [CLIと表示の契約](cli.md) に定める。行と状況の定義は [`spec/group_lifecycle.qnt`](../../spec/group_lifecycle.qnt)、評価範囲は [`spec/candidate_evaluation.qnt`](../../spec/candidate_evaluation.qnt) がモデルとして検査し、その範囲は各 `.qnt` の冒頭にある。

## 一覧の行と状況

`axon tasks` は Issue と Group の行を同じ並びに置く平らな一覧で、Group を見出しにした木にはしない。行は [候補集合](lifecycle.md#候補集合) の浮上した未着手と着手中を合わせたものである。

| 行 | 条件 |
| --- | --- |
| Issue | 保存値が `NotStarted` で自身と全祖先が浮上しているもの、または浮上に関係なく `InProgress` のもの |
| Group | 保存値が `NotStarted` で、自身と全祖先が浮上しているか、浮上に関係なく `InProgress` の Issue を子孫に持つもの |

完了済みの子孫だけで実効値が `InProgress` の Group は、自身と全祖先が浮上しているときだけ一覧に出る。祖先が `Undecided` でも、採用済みで浮上している Issue・Group は一覧に出る。

### Issue の行の状況

| 状況 | 条件 |
| --- | --- |
| `Ready` | 着手候補 |
| `InProgress` | `InProgress` |
| `Blocked` | 上のどちらでもない。祖先の採用、または自身・祖先の依存先の完了を待つ |

着手中に追加した未完了の依存先は、その Issue の行の問題として表示する（[表記](cli.md#一覧)）。

### Group の行の状況

Group の行の状況は配下から導出し、次の表を上から順に見て最初に当たるものを一つ示す。Group の `Ready` は Group 自身への操作ではなく、配下に着手できる Issue があることを示す。

| 状況 | 条件 |
| --- | --- |
| `Empty` | 直属の子がない。最終確認が通れば完了できる場合も `Empty` |
| `Confirmable` | 最終確認が通れば `Complete` できる |
| `Ready` | 着手候補の Issue を子孫に持つ |
| `InProgress` | 実効値が `InProgress` |
| `Blocked` | 直属の子があり、上のどれにも当たらない |

`Blocked` は残余として定義し、五つの状況で Group の行を必ず分類する。完了済みの子孫だけを持ち着手中の子孫がない Group も `InProgress` のままにする。

### 詰まっている Group と理由

完了できず、着手候補の子孫も着手中（`InProgress`）の Issue の子孫もない Group の行を、詰まっている Group とする。`Blocked` の行はすべて該当し、完了済みの子孫はあるが着手中の子孫がない `InProgress` の行と、完了できない `Empty` の行も該当する。`Confirmable` の行、`Ready` の行、完了できる `Empty` の行は該当しない。着手中の Issue に後から追加した未完了の依存先はその Issue の行の問題とし、その Issue の祖先を詰まっているとは見なさない。

詰まっている Group には、次の理由を導出する。`axon tasks` の行に限らず、`axon show` の対象になる保存値 `NotStarted` の Group にも同じ導出を使い、詰まっている Group には少なくとも一つの理由が当たる。

| 理由 | 条件 |
| --- | --- |
| 未完了の dependency | 自身、全祖先、または終了していない子孫のいずれかの依存先が `Completed` でない |
| `Undecided` の子 | 直属の子に `Undecided` がある |
| 未終了の子 Group | 直属の子 Group に終了していないものがある |
| 浮上していない着手可能な子孫 | 着手可能だが浮上していない Issue を子孫に持つ |
| `Undecided` の祖先 | 祖先に `Undecided` がある |
| 採用済みでない祖先 | 祖先に保存値が `Undecided`・`NotStarted` 以外のもの（終了した祖先）がある、または祖先の連なりが衝突中か保存先に無い祖先で切れる（[構造の違反](storage.md#構造の違反と修復) と統合の衝突で生じる） |
| 浮上していない祖先 | 祖先のいずれかの条件が未成立（終了した祖先とそれより下の祖先は評価しない） |
| 自身の再浮上条件が未成立 | 全祖先が浮上していて、Group 自身の条件が未成立 |

祖先は上から評価して未成立の祖先より下は評価しないため、浮上していない祖先がある Group には、自身の再浮上条件が未成立という理由は付かない。終了した祖先は条件を評価しないので、その配下では浮上していない祖先ではなく採用済みでない祖先として示す。自身の条件だけで隠れている着手可能な子孫は、浮上していない着手可能な子孫としても示す。

再浮上条件を評価しない `axon list` と `axon show --skip-conditions` は、条件をすべて成立したものとして状況と理由を導出する。着手候補の代わりに着手可能な Issue を使うため、Group の `Ready` は着手可能な Issue を子孫に持つことを指し、浮上していない着手可能な子孫、浮上していない祖先、自身の再浮上条件が未成立という理由は現れず、Issue に `Unsurfaced` も現れない。

## 条件の種類

再浮上条件は、未設定と外部コマンドだけを持つ。一つの Entity に設定できる外部コマンドは一つで、変更は置き換え、解除は未設定への変更とする。

| 条件 | 意味 |
| --- | --- |
| 未設定 | 常に成立する |
| 外部コマンド | 実行時の観測結果から成立・未成立・判定失敗を得る |

`axon condition set` は一つの shell 文字列を保存・置換し、`axon condition unset` は未設定へ戻す。どちらも終了した Entity に使え、条件を評価せず、lifecycle を変えず、記録として残る。空白だけのコマンドは拒否する。

## 条件の許可

外部コマンドの条件は、このマシンで許可された文字列だけを実行する。`.axon/` を Git で追跡する repository では、他人が書いた条件が merge・checkout・clone で記録として入り、読むだけの操作で利用者の権限で実行されうるためである。許可は記録ではなく、記録の形式と条件の shell 文字列は変えない。この方式にした理由と採らなかった案は [設計判断](../design/decisions.md#再浮上条件を許可リストで実行する理由) にある。

### 許可と digest

許可は条件の文字列の digest の集合で表す。digest は条件の文字列の UTF-8 bytes の BLAKE3 hash を小文字 16 進 64 文字で表したもので、接頭辞を持たない。条件の文字列が同じなら、どの Entity の条件でも同じ digest になり、一度の許可で同じ文字列のすべての条件を実行してよくなる。CLI では完全な 64 文字だけを受け付け、suffix では解決しない。

Axon が許可を増やす経路は次の三つだけである。

| 経路 | 許可するもの |
| --- | --- |
| `axon condition set ID --command CMD` | 指定した `CMD`。保存値が既に同じ文字列で `No changes` になる場合も許可する |
| `axon capture --command CMD` | 指定した `CMD` |
| `axon condition allow ID [--digest DIGEST]` | 対象 Entity の現在の条件の文字列 |

Git で取り込んだ記録（merge・rebase・cherry-pick・checkout・clone）、`axon resolve` で採った head の値、`axon convert` などで保持された既存の値は許可しない。`axon condition unset` は許可を変えない。許可の file のない環境で設定された条件は未許可になる。

許可するかの判断は、本文を含まない `axon condition unapproved` と `axon condition allow` の出力で行う（[表記](cli.md#再浮上条件の許可)）。

許可を取り消すコマンドは持たない。取り消すには、利用者が許可の file から該当する digest の行を消すか、file を消してすべての許可を捨てる（[形式](storage.md#axon-が-axon-の外に書くもの)）。

自動の許可は条件の記録の公開が確定した後（Applied）に書く。公開の結果が不明（Result unknown）なら許可を書かない。許可を書けなかった場合も記録は適用済みで、[CLIと表示の契約](cli.md#再浮上条件の許可) のとおり成功として終える。条件の設定・解除は許可の保存場所の状態によらず記録を書けるため、壊れた条件の修復は許可を読めない場合も行える。

`axon condition allow` は、完全な ID で指定した対象 Entity の条件が外部コマンドで、Entity が衝突中でない場合だけ許可する。ほかの Entity が衝突中でも許可できる。`--digest` を与えた場合は現在の文字列の digest と一致しなければ拒否し、確認してから許可するまでに文字列が変わっても、確認していない文字列を許可しない。`--digest` を省いた場合はこの照合を行わない。どちらでも、成功時は許可した文字列と digest を必ず示す。許可は記録を作らず、`axon log` に現れない。

### 未許可の条件の評価

評価の範囲（[評価契約](#評価契約)）に入った条件のうち、外部コマンドで digest が許可の集合にないものを未許可とする。未許可の条件は実行せず、浮上の判定では成立として扱う。未許可は判定失敗ではなく、一覧の取得や表示を失敗させない。

- 未許可の Entity は隠さず `axon proposals`・`axon tasks`・`axon show` に出し、その Entity 自身の行と状況欄に `+Unapproved` の印を付ける（[表記](cli.md#一覧)）。祖先の条件が未許可でも、配下の Entity には印を付けない。
- 評価の範囲を決める規則は許可によって変えない。未許可の祖先は成立として扱うので、成立した祖先と同じくその配下を評価する。このため、外からの変更で祖先の条件の文字列が変わって祖先が未許可になると、配下の許可済みの条件がそれまでより早く実行されうる。実行されるのは利用者が許可した文字列だけなので、この順序の変化は許容する。
- 未許可の条件も一回の取得で一回だけ判定し、結果を共有する。範囲外の条件は、許可されていなくても未許可として数えず、印も付けない。
- 未設定の条件は未許可にならない。

未許可の Entity が一件以上あった呼び出しは、件数と確認の方法を stderr に一行で示す。件数は、その呼び出しで評価の範囲に入り未許可だった Entity の数で、行として示さないのに評価する Entity も数えるため、印の付いた行の数より多くなりうる。

### 許可を読む時点と読めない場合

評価する経路（`axon proposals|tasks|show`）は、許可の集合を一回の一覧取得または表示の開始時に、記録の集合を読んだ後で一度だけ読む。評価中に別の process が許可を加えても、その取得の結果は変わらない。`axon list` と `--details` のない `axon show --skip-conditions` は許可を読まない。

許可の保存場所に file がなければ、許可の集合は空とする。file を読めない場合（読取の失敗、通常の file でない、[形式](storage.md#axon-が-axon-の外に書くもの) に合わない内容、Git 外で状態 directory を決められない、Git 内で許可の file を置く common Git directory を求められないか、その場所を [信頼できない](storage.md#axon-が-axon-の外に書くもの)）は次のように扱う。

- 評価する経路では、評価の範囲のすべての外部コマンドの条件を未許可として扱い、何も実行せずに続ける。評価の範囲に外部コマンドの条件が一つ以上あれば、読めなかったことを stderr に一行で示す。
- `axon show --details` は対象の許可を「不明」と示し、表示を失敗させない。
- `axon condition unapproved` と `axon condition allow` は、許可の状態を答えられないためエラーにする。
- 自動の許可は、書けなかったことを示す。読めない file は上書きしない。

### 許可の範囲と保存場所

許可の範囲は、Git 内では clone、Git 外では管理 root とし、範囲が異なれば同じ文字列でも改めて許可する。保存場所は Git で追跡されず、`.axon/` の中には置かない。後で `.axon/` を追跡し始めても、許可が commit されないためである。

| 保存先 | 許可の file | 範囲 |
| --- | --- | --- |
| Git 内 | common Git directory の `axon-condition-approvals` | その clone。linked worktree 間で共有し、clone ごとに分かれる |
| Git 外 | 状態 directory の下の `axon-condition-approvals/<key>` | その管理 root。`<key>` は保存先の store ID と管理 root の path から作る。管理 root を移動・改名するか、同じ path に store ID の異なる保存先を置くと、改めて許可する |

Git 外の状態 directory、`<key>`、file の形式と同時書込の扱いは [保存と統合の契約](storage.md#axon-が-axon-の外に書くもの) に定める。

許可は条件の文字列そのものを対象にする。許可した条件が参照する script・環境変数・作業 tree の file の内容が後で変わることは対象外とする。`.git`（directory か gitfile）を含む directory ごと複製・受け取った repository が持ち込む許可の file も対象外とする。`.git` を含まずに Git directory を作れる構成（bare repository の形の directory と `core.worktree`）は対象外にせず、Git directory が worktree root 直下の `.git` に由来しなければ許可を読めない場合として扱う（[規則](storage.md#axon-が-axon-の外に書くもの)）。

## 評価契約

条件が未設定なら常に浮上する。設定済みの条件は、その時点で候補に出してよいかを判定し、表示によって消費しない。成立後も再評価し、外界が変われば未成立や判定失敗にもなりうる。

再浮上条件は候補の表示と、`axon show` の状況・理由の表示にだけ使う。明示操作は lifecycle・包含・dependency の許可条件だけを使い、再浮上条件を評価しない。`axon list` と `axon show --skip-conditions` も条件を実行しない。条件の設定・訂正・解除も評価せずに行う。

評価する範囲は次のとおりとする。

- `axon proposals` は保存値が `Undecided`、`axon tasks` の浮上判定は保存値が `NotStarted` の Issue・Group を対象とし、どちらも dependency の完了や祖先の採用を要求しない。終了した Entity と対象外の状態は、自身の表示のためには評価しない。
- 実効値が `InProgress` の Group も保存値は `NotStarted` なので、`axon tasks` は自身の浮上判定として評価し、判定に失敗すれば一覧の取得を失敗させる。`InProgress` の Issue を子孫に持つ Group は浮上していなくても行には出るが、その配下は浮上しないため着手候補にならない。
- `InProgress` の Issue は浮上に関係なく `axon tasks` に加え、条件を評価しない。Issue は子を持たないため、祖先としても評価しない。
- `--kind`・`--label`・`--search` の絞り込みでは、残った候補とその祖先を評価し、除外された候補は自身の表示のためには評価しない。残った候補の祖先は kind や label が異なっても評価する。例外として `axon tasks` は、残った Group の行の状況を導出するため、その子孫の着手可能な Issue と、それらと残った Group の間にある Group を、絞り込みで除外されていても上から評価する。
- 残った候補の祖先を上から評価し、祖先が非浮上ならその配下を評価しない。終了した祖先は評価せず、その配下を非浮上として扱う。衝突中の祖先と記録のない祖先（[構造の違反](storage.md#構造の違反と修復)）は現在値も条件も持たないので評価せず、祖先の連なりはそこで切れる。その配下は残りの連なりだけで浮上の可否を決め、着手可能にはならない（`Blocked`）。
- `axon show ID` は、対象が `axon tasks` の行になる場合にその行が必要とする範囲だけを評価する。保存値が `NotStarted` の対象について、祖先の chain、対象自身、Group なら配下の着手可能な Issue と、それらと対象の間にある Group を上から評価する。`Undecided`・`InProgress`・終了した対象は何も評価しない。所属・依存先・依存元・子孫ツリーなど関連する Entity の行は、この範囲で得た結果だけを使い、範囲外の条件は成立したものとして状況を導出する。このため、範囲外の条件を持つ Entity は、関連する行では `Ready`・`Blocked` でも、その Entity 自身の `axon show` では `Unsurfaced` になりうる。
- 範囲に入った条件が [未許可](#未許可の条件の評価) なら実行せず、成立として扱う。
- 一回の一覧取得または表示で各 Entity を最大一回評価し、子や別の参照から同じ結果を共有する。次の取得では結果を引き継がない。
- 取得開始時に読んだ記録の集合を使い、評価中は書込み transaction を保持しない。衝突中の Entity（[保存と統合の契約](storage.md#現在値の導出)）は現在値を持たないため、どの候補集合にも入らず、条件を評価しない。子孫の導出では存在しない Entity として扱い、衝突中の子だけを持つ Group の行は子のない Group として導出する。衝突中の祖先は採用済みでない祖先として扱い、その配下の Issue は着手可能にならない。

必要な判定が一件でも失敗したら、一覧の取得または表示自体をエラーとする。未成立へ丸めず、判定できた一部の候補を成功結果として stdout へ返さない。`axon show` の判定失敗の診断は、`--skip-conditions` で保存情報を読めることを示す。

## 外部コマンドの実行

### 結果の解釈

| 実行結果 | Axon の扱い |
| --- | --- |
| 終了コード `0` | 条件成立 |
| 終了コード `1` | 条件未成立 |
| その他の終了コード、起動失敗、シグナル終了、タイムアウト | 判定失敗。候補一覧の取得自体をエラーにする |

[未許可](#未許可の条件の評価) の条件は実行しないため、この表の対象にならない。利用するツールが終了コード `1` を実行エラーに使う場合などは、条件コマンド側で変換する。stdout の内容を成立判定には使わない。

### 実行環境と責任範囲

条件はシェル文字列として保持し、`/bin/sh -c` で実行する。標準入力は閉じる。呼び出し元の環境変数を継承し、対話・ログイン用の shell 設定は読み込まない。

作業ディレクトリは、呼び出した Git worktree のルートとし、Git 外では Axon の管理ルートとする。条件を設定したときの worktree には結び付けないため、同じ条件でも実行する worktree のファイル・ブランチによって観測結果が変わりうる。相対パスの実行対象がない場合なども、成立判定の代替はせず、上の実行結果の契約に従って失敗を扱う。

### タイムアウトと中断

タイムアウトは外部コマンド1件ごとに適用し、`axon proposals|tasks|show` の `--condition-timeout` で呼び出し単位に指定できる。条件の保存値には含めない。

各評価を専用の process group で起動する。タイムアウトまたは Ctrl-C ではその group へ TERM を送り、終了していなければ KILL する。同じ group の子プロセスも終了対象にし、Axon の待機を終えるだけで放置しない。タイムアウトは未成立へ丸めず判定失敗とする。Ctrl-C では一覧取得を中断し、成功した候補一覧としては返さない。

### 出力と診断

正常終了（`0` / `1`）の stdout・stderr は、通常の候補一覧に混ぜない。判定失敗の診断と `--trace-conditions` は stdout・stderr を表示するが、秘密情報の自動除去は保証しない。
