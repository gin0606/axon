# デスクトップアプリ（GPUI）

`crates/axon-gui` は GPUI で作るデスクトップアプリの crate で、binary `axon-gui` と、UI テストが使う library を持つ。CLI とは別 crate とし、CLI 単体のビルドに GPUI を要求しない。層の位置づけは [層構造の地図](architecture.md) を参照する。

アプリは Axon の記録を閲覧するだけで、記録を変更する操作を持たない。記録の作成・編集・Note の追加・状態や構造の変更は CLI とエージェントが行う。

## 読み取り専用にした理由

アプリは当初、CLI を使わずに日常の仕事管理を完結させるため、作成・編集・Note の追加・状態と構造の変更を持っていた。2026-10-07 に、需要が少ないことと、独立した課題管理アプリとして保存の失敗と結果不明、二度押し、プロジェクト作成の中断などを考え続ける負担が大きいことから、記録の書き込みは CLI とエージェントに任せ、アプリは閲覧に限ると判断した。記録を変更する操作は、そのコードとテストごと取り除いた。必要になれば Git の履歴から戻せる。

プロジェクトの作成は、アプリの保存場所に保存先を初期化する処理として残っている。

## 起動と検証

workspace の `default-members` に GUI を含めないため、root の `cargo build`・`cargo run` は CLI だけを対象にする。GUI は package を指定して起動・検証する。

```sh
cargo run -p axon-gui
cargo test --locked -p axon-gui
```

実データに触れずに試すときは、環境変数 `AXON_GUI_DATA_DIR` に絶対パスを指定してデータの保存場所を置き換える（例: `AXON_GUI_DATA_DIR=/tmp/axon-try cargo run -p axon-gui`）。相対パスは起動場所に依存するため拒否する。

UI テストは GPUI の test platform 上の headless window で動き、ディスプレイや GPU を使わない。`--workspace` を付けた full verification は GUI も対象に含める。手順は [検証方針](verification.md) にある。

## 採用した依存

| crate | 指定 | 役割 |
| --- | --- | --- |
| `gpui-kit` | `=0.7.1` | GPUI、GPUI Base、GPUI Component と既定 asset の facade。アプリは GPUI を `gpui_kit` 経由で使う |
| `gpui-pre` | `gpui-kit` が `=0.3.8` に固定 | Zed の GPUI の snapshot。直接は依存しない |

版は exact 指定と `Cargo.lock` で固定し、開発ブランチや Git 依存には追従しない。更新するときは版を上げる変更として、この文書の要件と確認結果も見直す。一次資料は [GPUI Kit の導入手順](https://gpui-kit.com/docs/installation/) と [v0.7.1 の Cargo.toml](https://github.com/longbridge/gpui-kit/blob/v0.7.1/Cargo.toml)。

GPUI は serde_json の `preserve_order` を有効にするため、GUI と同じ build では CLI・コアの serde_json も挿入順の map になる。記録の canonical bytes がこれに依存しないよう、コアは記録者 metadata のキーを整列して書く（[記録 file と codec](lifecycle-file.md#記録-file-と-codec)）。

## 保存場所の規則

データの保存場所は OS のユーザーデータ領域（`dirs::data_dir()`）の下のアプリ用ディレクトリで、起動ディレクトリには依存しない。

| OS | 既定の保存場所 |
| --- | --- |
| macOS | `~/Library/Application Support/Axon` |
| Linux | `$XDG_DATA_HOME/axon`（未設定なら `~/.local/share/axon`） |
| Windows | `%APPDATA%\Axon` |

```text
<保存場所>/
    instance.lock          アプリの起動中に保持する単一起動 lock
    projects.json          プロジェクト一覧: ID・表示名・作成状態
    projects/<ID>/.axon/   各プロジェクトの保存先（CLI と同じ既存形式）
```

- プロジェクトごとに `projects/<ID>/` を管理 root とし、`axon init` と同じ初期化で `.axon/` を作る。ID は 12 桁の小文字 16 進の乱数で、日本語を含む表示名とは独立している。表示名は一覧にだけ保存し、保存先のパスに使わない。Entity ID の prefix はすべてのプロジェクトで `axon` とする。
- アプリは保存先を自分の管理 root として `Location::standalone` で開き、保存場所が Git の作業ツリー内にあっても Git を実行・参照しない。CLI から読むには `axon storage check <保存場所>/projects/<ID>` のように管理 root を指定する。
- `projects.json` は `{"format": 1, "projects": [{"id", "name", "status"}]}` の JSON で、一時 file への書き込みと rename で丸ごと置き換える。file がなく、`projects/` に `.axon/` を持つディレクトリも調べられないディレクトリもなければ、初回起動として空の一覧から始める。読めない・解釈できない・未知の `format` の一覧や、file だけが失われて保存先が残っている状態は空として扱わず、作成も含めて書き換えない。作成と再試行は、画面が保持する一覧ではなくその時点の file を読み直して変更する。名前の規則は新しく作る名前に適用し、保存済みの名前は規則が後で変わっても読み込める。
- 作成は、ディレクトリの作成 → 一覧へ `creating` で登録 → 保存先の初期化 → `ready` へ更新の順に進む。登録前に失敗すれば何も登録されず、そのまま作り直せる。一覧の置き換え後に永続化だけが失敗した場合は登録済みとしてディレクトリを残す。失敗後は一覧を読み直し、失敗が示すプロジェクトが登録されていればそれを選ぶ。一覧上は完了していても保存の永続化を確認できなかった場合は、その旨を左列に示す。登録後に失敗したプロジェクトは一覧に「作成未完了」として残り、「作成を再試行」で続きから完了できる。再試行は既存の `.axon/` を初期化し直さず、中断した初期化の残骸以外のファイルがあれば拒否する。`ready` にする前に保存先のディレクトリを永続化し、初期化の最後の同期だけが失敗した保存先も再試行で完了する。既存のディレクトリは新しいプロジェクトに再利用しない。
- `ready` のプロジェクトの保存先が見つからない・読めない場合はエラーとして表示し、空のプロジェクトとして扱わず、初期化もしない。管理 root、`.axon/` の header、記録ディレクトリのいずれかがなければ欠けた path を示して「保存先がない」とし、作り直しを促さない。他のプロジェクトへはそのまま切り替えられる。
- 単一起動 lock は OS の file lock（Unix では `flock`）で、起動から終了まで保持する。同じ保存場所で二つ目を起動すると、データを開かずに説明のウィンドウだけを表示する。異常終了すると OS が lock を解放するため、次の起動は妨げられない。

## 要件

- Rust: GUI の `rust-version` は 1.95。固定した依存の一部が 1.95 で安定化した標準ライブラリ API を使う。pull request の CI とリリース前の検証で `cargo +1.95.0 check --locked -p axon-gui --all-targets` を実行する。CLI の MSRV（`Cargo.toml` の 1.89）は GUI に合わせて上げない。
- macOS: 15 以上と Xcode Command Line Tools（GPUI Kit の要件）。
- Linux: ビルドに `gcc g++ clang libfontconfig-dev libwayland-dev libxkbcommon-x11-dev libx11-xcb-dev` を使う。CI は Ubuntu 24.04 でこれを導入し、ビルド・lint と headless の UI テストだけを行う。リンクは x86_64 Linux の Rust 既定である LLD を前提にする。window の表示には Wayland または X11 の session と Vulkan driver が要る。
- Windows: GPUI Kit は Windows 10 以上、MSVC toolchain、Visual Studio 2022 Build Tools、CMake を要件とする。

## 操作の仕様

ウィンドウの左列でプロジェクトを切り替え・作成する。切り替えはメニューから選び、作成は「＋ プロジェクトを作成」で名前欄を開いて Enter か「作成」で確定する。名前は前後の空白を除き、空、80 文字超、改行などの制御文字・行区切り・ゼロ幅や双方向制御などの書式文字・ハングルの埋め字などの見えない文字（ゼロ幅非接合子・接合子 U+200C・U+200D とタグ文字 U+E0020〜U+E007F は拒否しない。これらと異体字セレクタ U+FE00〜U+FE0F・U+E0100〜U+E01EF と空白だけの名前は空として拒否する）、既存と同じ名前を理由付きで拒否し、入力は残す。作成中は二度目の確定を受け付けない。作成中に別のプロジェクトへ切り替えた場合は、完了後もその選択を保ち、作成が途中で止まったときは左列で知らせる。作成や再試行の失敗理由は、切り替えて戻っても作成未完了のプロジェクトに残る。中央の列の上部には選んだプロジェクトの名前、保存先の状態（読み込み中、件数、読み直し中、読み込み失敗と再読み込み、作成未完了と再試行）、保存先のパスを示す。起動時は一覧の先頭のプロジェクトを開く。ウィンドウの最小サイズは 880×520 で、左列・一覧・詳細が横に並んだまま操作要素が収まる。

保存先の読み取りは `crates/axon-gui/src/project/` が GPUI に依存せずに担う。`ProjectConnection` は作成時に固定した管理 root を `Store::read` で読むだけで、保存先の lock を取らず、記録を書き込まない。window は disk I/O を background executor で実行し、`Requests` が発行した最新の要求の結果だけを適用するため、切り替え前に始めた遅い読み込みの結果は表示されない。

### 共通一覧と詳細

左列のプロジェクトの下に絞り込みを置く。状態（未判断・未着手・着手中・完了・取りやめ・衝突）、種類（Issue・Group）、label をチェックボックスで選び、中央の検索欄の文字列と組み合わせる。同じ項目の中の選択は OR、項目どうしと検索は AND で、ある項目の選択をすべて外すと一致はゼロ件になる。状態は実効値で判定し、保存値が未着手の Group は、直下の子の実効値が着手中か完了なら着手中になる（[Group の実効 lifecycle](../reference/lifecycle.md#group-の実効-lifecycle)）。衝突中の Entity は lifecycle を持たないため「衝突」として扱い、種類・label・検索は最初の head の値で判定する。検索は `axon list --search` と同じく、タイトルと本文に対する大文字小文字を区別する部分一致である。「衝突」の選択肢は、最後に読み込んだそのプロジェクトの記録に衝突中の Entity がある間だけ出す。出していない間は「衝突」を選択済みとして扱い、外したまま隠れた選択が後で起きた衝突を一覧から隠すことはない。プロジェクトを切り替えると、読み込みが終わるまで選択肢を出さず、前のプロジェクトの衝突の有無を引き継がない。このため、外していた「衝突」は切り替えで選択済みに戻る。同じプロジェクトの読み直し中と読み込み失敗の間は、前回の読み込みでの有無に従う。初期値は未判断・未着手・着手中・衝突、両方の種類、すべての label で、「絞り込みを初期値に戻す」で検索とともに戻る。絞り込みはプロジェクトを切り替えても保つ。

中央の一覧は「階層」と「フラット」を切り替えられ、初期表示は階層とする。階層では包含に沿って字下げし（字下げは 8 段までで、それより深い Entity も 8 段で示す）、兄弟は作成順に並べる。一致した Entity の祖先が一致しない場合は「参考表示」と明記して薄く表示し、件数は「N 件が一致 / 参考表示の親 M 件」のように一致件数から除く。親が記録にない Entity と包含の循環の最初の Entity は最上位に置き、各 Entity は一度だけ現れる。フラットは一致した Entity だけを作成順に並べる。各行は状態の記号とタイトル、Issue / Group・状態・状況（着手可・前提待ち・完了確認待ちなど）・label を示す。タイトルの行と種類・状態などの行は折り返さず切り詰め、すべての行を同じ高さにする。一覧は表示範囲の行だけを組み立てるため、描画の時間は記録の件数に比例しない。行をクリックすると詳細を開く。一覧は Tab でもフォーカスでき、フォーカスがある間は上下の矢印キーで選択を移し、選んだ行が見える位置までスクロールする。プロジェクトに Entity がない場合と、絞り込みに一致しない場合は別の文言で示し、後者には初期値に戻すボタンを出す。別のプロジェクトへ切り替えた後の読み込み中と、読み込み失敗の間は前回の一覧を表示しない。

右列は選んだ Entity の詳細で、上から Issue / Group・label・ID の行と「閉じる」、タイトル、状態（Group の実効値が保存値と異なる場合は両方）と状況、所属（祖先の列）、衝突と構造の違反（あれば）、前提待ちの理由（着手・完了の前提、止まっている Group の理由）、本文、保存された再浮上条件、子と子孫の件数、依存先、この仕事に依存している Entity、Note、履歴を示す。祖先・子・依存先・依存元・前提待ちの理由・違反に出る Entity はクリックで詳細へ移れ、記録にない ID はそのまま示す。選んだ Entity が絞り込みに一致しなくなっても詳細を閉じず、一致しないことと、一致しない項目（選んでいない状態・種類・label、本文とタイトルにない検索語）を示す。「閉じる」で詳細を閉じると、右列は空の表示に戻る。一覧に一致する行がある間だけ、一覧から選ぶよう促す一文を出す。詳細には操作の可否や操作の案内を出さない。

一覧と詳細は保存先を一度読んだ値（`crates/axon-gui/src/board/`、GPUI 非依存）から導き、表示の状況・前提・履歴はコアの `read::list`・`read::detail`・`read::history`・`read::notes` から変換する。再浮上条件のコマンドは実行せず、すべて満たしているものとして表示する。読み込みと行の導出は background executor で行い、プロジェクトを切り替えると選択を外して前のプロジェクトの結果を適用しない。

CLI などでの外部の変更は、一覧の「再読み込み」と、ウィンドウが前面に戻ったとき（アクティブになったとき）に選択中のプロジェクトを読み直して反映する。ファイルの監視はしない。前面に戻ったときは選択中のプロジェクトを読み直し、プロジェクトの一覧を読めなかった場合は状態の欄の「再読み込み」と同じく一覧から読み直す。ウィンドウが背面に回ったときは読まない。すでに読み込みやプロジェクトの作成が進んでいる間に前面に戻った場合は、その結果を表示し、読み込みを重ねない。その読み込みが始まった後の変更は、次に前面に戻ったときか「再読み込み」で反映する。同じプロジェクトの読み直しでは、結果が出るまで前回の一覧と詳細を表示し続け、状態に「読み直し中」と示す。絞り込み・階層とフラット・選択・一覧と詳細のスクロール位置は保ち、選択した Entity が残っていれば新しい記録の詳細に置き換える。読み直しに失敗した場合は前回の一覧を出さず、選択を外して失敗を示す。

### キーボードとメニュー

Tab と Shift-Tab はフォーカスを移す。一覧も Tab でフォーカスでき、フォーカスがある間は上下の矢印キーで選択を移す。プロジェクト名の欄では Enter で作成を確定する。ウィンドウを閉じるとアプリを終了する。macOS のメニューバーには終了と、編集（取り消す・やり直す・カット・コピー・ペースト・すべてを選択）を置き、編集は検索欄とプロジェクト名の欄で使う。

## 確認結果

2026-10-05、macOS 27.0.1（Apple Silicon）、Rust 1.98.0、上記の依存で次を確認した。

- `cargo run -p axon-gui` でウィンドウが開き、日本語のプレースホルダーと説明文が表示される。システムの外観（ライト・ダーク）に追従する。
- 当時の作業欄の headless UI テストで、日本語入力、Tab・Shift-Tab によるフォーカスの一巡、メニューの選択と閉鎖、当時の最小ウィンドウ（420×320）で全操作要素がウィンドウ内に収まることを確認した。この作業欄は 2026-10-07 に取り除いた。
- GUI の Rust 1.95.0 でのビルドと、CLI の Rust 1.89.0 での `cargo +1.89.0 check --locked --all-targets --all-features` が通る。
- Ubuntu 24.04（aarch64 の container、4 CPU、メモリ 7.7 GB、LLD でリンク）で上記の package を導入し、full verification の各 command が headless で通る。同じ環境で GNU ld を使うと、GUI の test binary のリンクがメモリ不足で失敗した。GitHub Actions の x86_64 runner では未実行。

2026-10-05、macOS 27.0.1（Apple Silicon）、Rust 1.98.0 でプロジェクトの保存と単一起動を次のように確認した。

- `crates/axon-gui/src/project/` の単体テストと `crates/axon-gui/tests/projects.rs` の headless UI テストで、独立した一時保存場所に日本語名のプロジェクトを二つ作り、別々の管理 root と既存形式の `.axon/` ができること、一方への書き込みが他方に現れないこと、同じ保存場所を開き直すと一覧と保存先の対応が復元されること、作成の各段階での失敗の検出と再試行、既存ディレクトリ・既存の保存先・無関係なファイルを置き換えないこと、読めない一覧・保存先をエラーとして扱い他のプロジェクトへ切り替えられること、切り替え前の遅い読み込み結果と再試行の結果を別のプロジェクトに表示しないこと、二重確定で一件だけ作ること、作成失敗時に名前を残すこと、一覧 file の喪失を初回起動と区別すること、Git の作業ツリー内の保存場所でも Git を参照しないこと、当時の最小ウィンドウ（640×400）で長い名前とエラー表示があっても当時の作業欄が収まること、メインウィンドウが単一起動 lock を保持し続けることを確認した。
- 単一起動 lock は同一 process 内の二重取得と、lock を持つ子 process を SIGKILL した後の再取得をテストで確認した。
- `/` を作業ディレクトリにして `AXON_GUI_DATA_DIR` を一時ディレクトリにした binary を起動し、lock が保持されること、二つ目の起動が lock を取らずデータを作らずに動き続けること、一つ目を SIGKILL すると lock が解放され、三つ目の起動が lock を取ることを確認した。画面の取得はできず、二つ目の説明ウィンドウとメインウィンドウの見た目は目視していない。

2026-10-05、macOS 27.0.1（Apple Silicon）、Rust 1.98.0 で共通一覧と詳細を次のように確認した。
