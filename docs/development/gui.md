# デスクトップアプリ（GPUI）

`crates/axon-gui` は GPUI で作るデスクトップアプリの crate で、binary `axon-gui` と、UI テストが使う library を持つ。CLI とは別 crate とし、CLI 単体のビルドに GPUI を要求しない。層の位置づけは [層構造の地図](architecture.md) を参照する。

アプリは、既存のリポジトリなどにある Axon の保存先（`.axon/` を持つ管理 root）を登録し、その記録を閲覧するだけで、記録を変更する操作を持たない。記録の作成・編集・Note の追加・状態や構造の変更は CLI とエージェントが行う。アプリが書き込むのは、アプリのデータ領域にある登録の一覧だけである。

## 読み取り専用にした理由

アプリは当初、CLI を使わずに日常の仕事管理を完結させるため、アプリのデータ領域にプロジェクトごとの保存先を作り、作成・編集・Note の追加・状態と構造の変更を持っていた。2026-10-07 に、需要が少ないことと、独立した課題管理アプリとして保存の失敗と結果不明、二度押し、プロジェクト作成の中断などを考え続ける負担が大きいことから、記録の書き込みは CLI とエージェントに任せ、アプリは各リポジトリの記録の閲覧に限ると判断した。記録を変更する操作と、アプリ専用の保存先を作る処理は、そのコードとテストごと取り除いた。必要になれば Git の履歴から戻せる。

## 起動と検証

workspace の `default-members` に GUI を含めないため、root の `cargo build`・`cargo run` は CLI だけを対象にする。GUI は package を指定して起動・検証する。

```sh
cargo run -p axon-gui
cargo test --locked -p axon-gui
```

普段の登録の一覧に触れずに試すときは、環境変数 `AXON_GUI_DATA_DIR` に絶対パスを指定してデータの保存場所を置き換える（例: `AXON_GUI_DATA_DIR=/tmp/axon-try cargo run -p axon-gui`）。相対パスは起動場所に依存するため拒否する。

UI テストは GPUI の test platform 上の headless window で動き、ディスプレイや GPU を使わない。`--workspace` を付けた full verification は GUI も対象に含める。手順は [検証方針](verification.md) にある。

## 採用した依存

| crate | 指定 | 役割 |
| --- | --- | --- |
| `gpui-kit` | `=0.7.1` | GPUI、GPUI Base、GPUI Component と既定 asset の facade。アプリは GPUI を `gpui_kit` 経由で使う |
| `gpui-pre` | `gpui-kit` が `=0.3.8` に固定 | Zed の GPUI の snapshot。直接は依存しない |

版は exact 指定と `Cargo.lock` で固定し、開発ブランチや Git 依存には追従しない。更新するときは版を上げる変更として、この文書の要件と確認結果も見直す。一次資料は [GPUI Kit の導入手順](https://gpui-kit.com/docs/installation/) と [v0.7.1 の Cargo.toml](https://github.com/longbridge/gpui-kit/blob/v0.7.1/Cargo.toml)。

GPUI は serde_json の `preserve_order` を有効にするため、GUI と同じ build では CLI・コアの serde_json も挿入順の map になる。記録の canonical bytes がこれに依存しないよう、コアは記録者 metadata のキーを整列して書く（[記録 file と codec](lifecycle-file.md#記録-file-と-codec)）。

## 保存場所の規則

アプリのデータの保存場所は OS のユーザーデータ領域（`dirs::data_dir()`）の下のアプリ用ディレクトリで、起動ディレクトリには依存しない。

| OS | 既定の保存場所 |
| --- | --- |
| macOS | `~/Library/Application Support/Axon` |
| Linux | `$XDG_DATA_HOME/axon`（未設定なら `~/.local/share/axon`） |
| Windows | `%APPDATA%\Axon` |

```text
<保存場所>/
    instance.lock   アプリの起動中に保持する単一起動 lock
    roots.json      登録の一覧: 登録した管理 root の絶対パス
```

- 登録する単位は管理 root（`.axon/` を持つディレクトリ）で、フォルダを選ぶダイアログで指定する。選んだパスは symlink・`.`・`..` を解決した絶対パスに正規化し、同じ管理 root は重複して登録しない。同じリポジトリの別の worktree は、管理 root が異なるため別の登録になる。
- 登録できるのは、ディレクトリであり `.axon/` の header（`.axon/header.json`）があるフォルダだけで、満たさなければ理由を示して登録しない。それ以外の保存先の状態（Git の index の unmerged、記録の破損など）は登録の可否に使わず、登録後にそのリポジトリの読み込みエラーとして示す。パスに UTF-8 で表せない文字を含むフォルダは一覧に保存できないため登録しない。
- アプリは登録した管理 root を、探索せずにコアの `Location::explicit` で開く（CLI の `axon storage check ROOT` と同じ指定）。Git の作業ツリー内では、CLI と同じく index の unmerged を検査する。読み取りはコアの `Store::read` だけで、保存先の lock を取らず、`.axon/` 配下に書き込まない。
- 登録先の管理 root か `.axon/` の header が見つからない場合は、欠けた path を示してそのリポジトリのエラーとし、空のリポジトリとして扱わず、作り直しを促さない。記録ディレクトリ（`.axon/records/`）がない場合は、CLI と同じく記録のない保存先として読む（Git は空のディレクトリを保持しないため、記録を作る前に commit した保存先の checkout にはない）。読めない・開けない場合も同様にエラーとして示す。ほかの登録へはそのまま切り替えられる。
- 登録の解除は一覧から外すだけで、登録先のファイルには触れない。解除したフォルダは再び登録できる。
- `roots.json` は `{"format": 1, "roots": ["<絶対パス>", ...]}` の JSON で、一時 file への書き込みと rename で丸ごと置き換える。file がなければ空の一覧から始める。読めない・解釈できない・未知の `format` の一覧は空として扱わず、登録・解除も含めて書き換えない。登録と解除は、画面が保持する一覧ではなくその時点の file を読み直して変更し、失敗した場合は一覧を読み直して表示する。
- 以前の版がアプリ専用の保存先に使っていた `projects.json` と `projects/` は読まず、消さない。そこにある記録を閲覧するには、`projects/<ID>` を管理 root として登録する。
- 単一起動 lock は OS の file lock（Unix では `flock`）で、起動から終了まで保持する。登録の一覧を変更する操作は lock を保持する起動だけが持ち、一つのアプリの中では一度に一つずつ行う。同じ保存場所で二つ目を起動すると、データを開かずに説明のウィンドウだけを表示する。異常終了すると OS が lock を解放するため、次の起動は妨げられない。

## 要件

- Rust: GUI の `rust-version` は 1.95。固定した依存の一部が 1.95 で安定化した標準ライブラリ API を使う。pull request の CI とリリース前の検証で `cargo +1.95.0 check --locked -p axon-gui --all-targets` を実行する。CLI の MSRV（`Cargo.toml` の 1.89）は GUI に合わせて上げない。
- macOS: 15 以上と Xcode Command Line Tools（GPUI Kit の要件）。
- Linux: ビルドに `gcc g++ clang libfontconfig-dev libwayland-dev libxkbcommon-x11-dev libx11-xcb-dev` を使う。CI は Ubuntu 24.04 でこれを導入し、ビルド・lint と headless の UI テストだけを行う。リンクは x86_64 Linux の Rust 既定である LLD を前提にする。window の表示には Wayland または X11 の session と Vulkan driver が要る。
- Windows: GPUI Kit は Windows 10 以上、MSVC toolchain、Visual Studio 2022 Build Tools、CMake を要件とする。

## 操作の仕様

ウィンドウの左列（狭い幅ではパネル。下の「ウィンドウの幅と列」）で、登録したリポジトリを切り替え・登録する。切り替えはメニューから選び、メニューの各項目は表示名とパスを示す。表示名は管理 root のディレクトリ名で、名前の入力・変更は持たない。「＋ リポジトリを登録」でフォルダを選ぶダイアログを開き、選んだフォルダを登録して選択する。ダイアログを閉じたときは登録を変えず、ダイアログを開いていた間は読まなかった選択中のリポジトリを読み直す。登録できない理由と、登録・解除の失敗は中央の列の上部に示す。すでに登録したフォルダを選んだ場合は、その旨を示してそのリポジトリを開く。一覧を読めない・保存できない失敗と、重複や未登録による拒否の後は、一覧を読み直して表示する。別のリポジトリへ切り替えると、その表示は消す。ダイアログを開いてから登録が終わるまでは、次の登録・解除を受け付けない。その間に別のリポジトリへ切り替えた場合は、登録後もその選択を保つ。中央の列の上部には選んだリポジトリの表示名、保存先の状態（読み込み中、件数、読み直し中、読み込み失敗と再読み込み）、管理 root のパスと「登録を解除」を示す。解除すると一覧の先頭のリポジトリを開く。起動時も一覧の先頭のリポジトリを開く。

登録の一覧と保存先の読み取りは `crates/axon-gui/src/project/` が GPUI に依存せずに担う。`ProjectConnection` は作成時に固定した管理 root を `Store::read` で読むだけで、保存先の lock を取らず、記録を書き込まない。window は disk I/O を background executor で実行し、`Requests` が発行した最新の要求の結果だけを適用するため、切り替え前に始めた遅い読み込みの結果は表示されない。

### ウィンドウの幅と列

ウィンドウの幅で、横に並べる列の数を決める（`crates/axon-gui/src/app.rs` の `Columns`）。

| 幅 | 列 |
| --- | --- |
| 980 以上 | 左列（リポジトリと絞り込み）・一覧・詳細 |
| 700 以上 980 未満 | 一覧・詳細 |
| 700 未満 | 一覧か詳細のどちらか |

左列を出さない幅では、中央の列のタイトルの横の「リポジトリと絞り込み」で、左列と同じ内容をウィンドウの左に重ねたパネルとして開く。絞り込みが初期値と異なる間は、ボタンに「（変更あり）」と添えて、一覧に出ない Entity があることを示す。パネルは「閉じる」、パネルの外のクリック、Escape で閉じ、リポジトリを切り替えたときも閉じる。絞り込みを変えても閉じない。開いている間はフォーカスを一覧から外し、矢印キーが裏の一覧を動かさないようにする。

一列の幅では、行をクリックするか、一覧にフォーカスがある間に Enter を押すと、一覧の代わりに詳細を表示する。矢印キーでの選択の移動は一覧を表示したまま行う。詳細の「閉じる」は「一覧に戻る」になり、選択を保ったまま一覧に戻ってその行を表示し、一覧にフォーカスを移す。Escape でも戻る。詳細の中のリンクでの移動は詳細のまま行う。

ウィンドウの最小サイズは 380×460 で、どの幅でも一覧・詳細・パネルの操作要素がウィンドウに収まる。

### 共通一覧と詳細

左列（またはパネル）のリポジトリの下に絞り込みを置く。状態（未判断・未着手・着手中・完了・取りやめ・衝突）、種類（Issue・Group）、label をチェックボックスで選び、中央の検索欄の文字列と組み合わせる。同じ項目の中の選択は OR、項目どうしと検索は AND で、ある項目の選択をすべて外すと一致はゼロ件になる。状態は実効値で判定し、保存値が未着手の Group は、直下の子の実効値が着手中か完了なら着手中になる（[Group の実効 lifecycle](../reference/lifecycle.md#group-の実効-lifecycle)）。衝突中の Entity は lifecycle を持たないため「衝突」として扱い、種類・label・検索は最初の head の値で判定する。検索はタイトル・本文・ID に対する大文字小文字を区別する部分一致である。タイトルと本文だけを見る `axon list --search` と違って ID も対象にし、CLI の出力などで見た ID から、完全 ID でも CLI が受け付ける suffix でもその一部でも Entity を探せる。ただし、絞り込みで外れた状態の Entity は ID で検索しても一覧に出ない。「衝突」の選択肢は、最後に読み込んだそのリポジトリの記録に衝突中の Entity がある間だけ出す。出していない間は「衝突」を選択済みとして扱い、外したまま隠れた選択が後で起きた衝突を一覧から隠すことはない。リポジトリを切り替えると、読み込みが終わるまで選択肢を出さず、前のリポジトリの衝突の有無を引き継がない。このため、外していた「衝突」は切り替えで選択済みに戻る。同じリポジトリの読み直し中と読み込み失敗の間は、前回の読み込みでの有無に従う。初期値は未判断・未着手・着手中・衝突、両方の種類、すべての label で、「絞り込みを初期値に戻す」で検索とともに戻る。絞り込みはリポジトリを切り替えても保つ。

中央の一覧は「階層」と「フラット」を切り替えられ、初期表示は階層とする。階層では包含に沿って字下げし（字下げは 8 段までで、それより深い Entity も 8 段で示す）、兄弟は作成順に並べる。一致した Entity の祖先が一致しない場合は「参考表示」と明記して薄く表示し、件数は「N 件が一致 / 参考表示の親 M 件」のように一致件数から除く。親が記録にない Entity と包含の循環の最初の Entity は最上位に置き、各 Entity は一度だけ現れる。フラットは一致した Entity だけを作成順に並べる。階層では包含の段ごとに細い罫線を引き、同じ Group の行をひとまとまりに見せる。各行は状態の記号とタイトル、ID・Issue / Group・状態・状況（着手可・前提待ち・完了確認待ちなど）・label を示す。ID は 2 行目の先頭に置き、狭い一覧で切り詰められても見えるようにする。その分、ID の長さと一覧の幅によっては 2 行目の後ろにある「構造の違反」や「参考表示」の注記が切り詰められて見えなくなる。参考表示の行は薄く表示するため、注記が切れても区別できる。タイトルの行と種類・状態などの行は折り返さず切り詰め、すべての行を同じ高さにする。一覧は表示範囲の行だけを組み立てるため、描画の時間は記録の件数に比例しない。行をクリックすると詳細を開く。一覧は Tab でもフォーカスでき、フォーカスがある間は上下の矢印キーで選択を移し、選んだ行が見える位置までスクロールする。リポジトリに Entity がない場合と、絞り込みに一致しない場合は別の文言で示し、後者には初期値に戻すボタンを出す。別のリポジトリへ切り替えた後の読み込み中と、読み込み失敗の間は前回の一覧を表示しない。

右列は選んだ Entity の詳細で、上から Issue / Group・label・ID の行と「閉じる」、タイトル、状態（未判断・未着手・着手中・完了を順に並べた線路の上の現在地として示し、取りやめと衝突は線路の外に示す）、状況（Group の実効値が保存値と異なる場合は保存値も示す）、所属（祖先の列）、衝突と構造の違反（あれば）、前提待ちの理由（着手・完了の前提、止まっている Group の理由）、本文、保存された再浮上条件、子と子孫の件数、依存先、この仕事に依存している Entity、Note、履歴を示す。祖先・子・依存先・依存元・前提待ちの理由・違反に出る Entity はクリックで詳細へ移れ、記録にない ID はそのまま示す。選んだ Entity が絞り込みに一致しなくなっても詳細を閉じず、一致しないことと、一致しない項目（選んでいない状態・種類・label、タイトル・本文・ID にない検索語）を示す。「閉じる」で詳細を閉じると、右列は空の表示に戻る。一覧に一致する行がある間だけ、一覧から選ぶよう促す一文を出す。詳細には操作の可否や操作の案内を出さない。

一覧と詳細は保存先を一度読んだ値（`crates/axon-gui/src/board/`、GPUI 非依存）から導き、表示の状況・前提・履歴はコアの `read::list`・`read::detail`・`read::history`・`read::notes` から変換する。再浮上条件のコマンドは実行せず、すべて満たしているものとして表示する。読み込みと行の導出は background executor で行い、リポジトリを切り替えると選択を外して前のリポジトリの結果を適用しない。

CLI などでの外部の変更は、一覧の「再読み込み」と、ウィンドウが前面に戻ったとき（アクティブになったとき）に選択中のリポジトリを読み直して反映する。ファイルの監視はしない。前面に戻ったときは選択中のリポジトリを読み直し、登録の一覧を読めなかった場合は状態の欄の「再読み込み」と同じく一覧から読み直す。ウィンドウが背面に回ったときは読まない。すでに読み込みや登録・解除が進んでいる間、またはフォルダを選ぶダイアログを開いている間に前面に戻った場合は、その結果を表示し、読み込みを重ねない。その読み込みが始まった後の変更は、次に前面に戻ったときか「再読み込み」で反映する。同じリポジトリの読み直しでは、結果が出るまで前回の一覧と詳細を表示し続け、状態に「読み直し中」と示す。絞り込み・階層とフラット・選択・一覧と詳細のスクロール位置は保ち、選択した Entity が残っていれば新しい記録の詳細に置き換える。読み直しに失敗した場合は前回の一覧を出さず、選択を外して失敗を示す。

### 配色

状態は、一覧の記号・絞り込みの選択肢・詳細の線路とリンクのどこでも同じ状態ごとの色で示す（未判断は紫、未着手は青灰、着手中は琥珀、完了は緑、取りやめは灰、衝突は赤）。それ以外は無彩色に近い灰青と墨で塗り、色の付いた要素が状態・リンクと選択・注意（前提待ち・絞り込みから外れた選択）・エラーのどれかを示すようにする。配色は `crates/axon-gui/src/app/style.rs` が持ち、システムの外観（ライト・ダーク）に追従して、入力欄・ボタン・チェックボックスが使う GPUI Component のテーマにも書き込む。

### キーボードとメニュー

Tab と Shift-Tab はフォーカスを移す。一覧も Tab でフォーカスでき、フォーカスがある間は上下の矢印キーで選択を移し、一列の幅では Enter で詳細を開く。Escape はパネルを閉じ、一列の幅では詳細から一覧に戻る。ウィンドウを閉じるとアプリを終了する。macOS のメニューバーには終了と、編集（取り消す・やり直す・カット・コピー・ペースト・すべてを選択）を置き、編集は検索欄で使う。

## 確認結果

2026-10-05、macOS 27.0.1（Apple Silicon）、Rust 1.98.0、上記の依存で次を確認した。

- `cargo run -p axon-gui` でウィンドウが開き、日本語のプレースホルダーと説明文が表示される。システムの外観（ライト・ダーク）に追従する。
