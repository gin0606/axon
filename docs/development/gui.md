# デスクトップアプリの開発

閲覧専用の範囲とデータ file の保証は [デスクトップアプリ](../reference/gui.md)、利用者向けの説明は [デスクトップアプリ](../guide/gui.md)、層の境界は [層の依存方向](architecture.md)、検証は [検証方針](verification.md) にある。この文書は、GUI を作り動かすための要件と依存の固定方針、確認結果を示す。

## 起動とアプリの作成

workspace の `default-members` に GUI を含めないため、root の `cargo build`・`cargo run` は CLI だけを対象にし、GUI は package（`axon-gui`）を指定して起動・検証する。

macOS で、アイコンと名前を持つアプリ（`Axon.app`）として使うときは [scripts/bundle-gui](../../scripts/bundle-gui) で作る。[cargo-bundle](https://github.com/burtonageo/cargo-bundle) の版は `mise.toml` で固定し、設定とアイコンの元は `crates/axon-gui/Cargo.toml` の `[package.metadata.bundle]` にある。macOS は、作った `.app` を一度開いたときに `axon gui` のリンクの宛先として認識する。macOS 版は [リリース](releasing.md) で CLI と同じタグから作り、Developer ID で署名・公証して cask で配布する。Windows と Linux は配布しておらず、アイコン（実行ファイルへの埋め込み、`.desktop` とアイコンの配置）は配布するときに足す。

`axon gui` を試すときは、普段の登録の一覧に触れないよう `open -a <Axon.app のパス> --env AXON_GUI_DATA_DIR=<絶対パス>` で起動してから、管理 root で `axon gui` を実行する。起動していない `.app` をリンクで起動すると、この環境変数は渡らず普段の保存場所を使う。

## 採用した依存

| crate | 役割 |
| --- | --- |
| `gpui-kit` | GPUI、GPUI Base、GPUI Component と既定 asset の facade。アプリは GPUI を `gpui_kit` 経由で使う |
| `sys-locale` | OS の優先言語一覧を取得する。対応言語の選択は GUI 内の純粋関数で行う |
| `rust-i18n` | 日本語・英語のカタログを埋め込み、実効言語を明示して文言を解決する。GPUI Component の使用中の文言にも日本語訳を補う |
| `gpui-pre` | Zed の GPUI の snapshot。版は `gpui-kit` が固定し、アプリは直接依存しない |
| `markdown` | GPUI Base が使う版にそろえる。本文と Note を描画する前に、GPUI Base と同じ構文の設定で構文木を得て、段落の中の改行を書き換える。画像を代替テキストで描く GPUI Base の Markdown の plugin も、この構文木の節を受け取る。HTML の `<img>` の代替テキストの文字参照も、この crate の HTML5 の名前付き文字参照の表で読む |

版は `crates/axon-gui/Cargo.toml` の exact 指定と `Cargo.lock` で固定し、開発ブランチや Git 依存には追従しない。使っている版はこの二つで確かめる。更新するときは版を上げる変更として、要件と確認結果も見直す。`markdown` は Dependabot の更新対象から外しており、`gpui-kit` を上げるときに GPUI Base が使う版へ手で合わせる。一次資料は [GPUI Kit の導入手順](https://gpui-kit.com/docs/installation/) と、使っている版のタグにある GPUI Kit の `Cargo.toml`。

## 要件

- Rust: CLI と同じく `rust-toolchain.toml` で固定した版を使う（[検証方針](verification.md)）。
- macOS: 15 以上と Xcode Command Line Tools（GPUI Kit の要件）。
- Linux: ビルドに `gcc g++ clang libfontconfig-dev libwayland-dev libxkbcommon-x11-dev libx11-xcb-dev` を使う。CI は Ubuntu 24.04 でこれを導入し、ビルド・lint と headless の UI テストだけを行う（[検証方針](verification.md)）。リンクは x86_64 Linux の Rust 既定である LLD を前提にする（GNU ld では、4 CPU・メモリ 7.7 GB の環境で GUI の test binary のリンクがメモリ不足で失敗した）。window の表示には Wayland または X11 の session と Vulkan driver が要る。
- Windows: GPUI Kit は Windows 10 以上、MSVC toolchain、Visual Studio 2022 Build Tools、CMake を要件とする。

## 確認結果

headless UI テストで確かめている振る舞いは `crates/axon-gui` のテストを正本とし、ここには実機での確認、計時、GPUI の挙動から決めた点、未確認の範囲を残す。

2026-10-07、利用者が macOS 27.0.1（Apple M6）の実機で、確認用の保存場所を `AXON_GUI_DATA_DIR` で指定して、閲覧専用への再編（記録を変更する操作の削除、前面に戻ったときの読み直し、管理 root の登録・解除・切り替え）を終えた時点の release build のアプリを起動・操作し、次の項目を問題なく確認した。登録したのは、このリポジトリ（約 1,900 file の記録）、日本語名のディレクトリにある CLI で作った一時的な管理 root（入れ子の Group、完了・着手中・未着手・未判断・取りやめの各状態、前提待ち、長いタイトル、Note を含む）、名前を変えて見つからなくする一時的な管理 root の三つである。

- フォルダを選ぶダイアログでの三つの登録、重複の登録でその旨を示して登録済みのリポジトリを開くこと、`.axon` のないフォルダの登録の拒否と理由の表示、ダイアログを閉じても登録が変わらないこと。
- 左列のメニューでの切り替えで、それぞれの記録だけが表示されること。検索欄での日本語 IME の変換と確定と、それによる絞り込み、状態・種類・label のチェックボックスと初期値に戻す操作、階層とフラットの切り替え。
- 行のクリックと矢印キーでの詳細の表示、前提待ちの理由、所属・依存先へのリンクでの移動、「閉じる」、日本語の Note と履歴の表示。
- CLI で Note の追加・採用・タイトルの変更をした後、ウィンドウを前面に戻すと一覧と詳細に反映されること。
- 登録先の管理 root を名前の変更で見つからなくすると、欠けた path を示すエラーになり、他の登録へ切り替えられること。
- 登録の解除で一覧から外れて先頭のリポジトリが開くこと、終了して起動し直すと登録が残ること、同じ保存場所で二つ目を起動すると説明のウィンドウだけが開くこと。
- 最小ウィンドウまで縮めたときの表示と長いタイトルの切り詰め、日本語の表示。
- 操作の前後で各管理 root の `.axon/` 配下の file とディレクトリの一覧・内容の SHA-256・大きさ・更新時刻を比べ、差分は確認の手順で CLI から書いた記録の追加だけで、アプリの操作による増減・変更がないこと。このリポジトリでは `git status` の `.axon/` の出力も変わらなかった。

2026-10-08、macOS 27.0.1（Apple Silicon）、Rust 1.98.0 で、配色と一覧・詳細の見た目を作り直した版を実機で次のように確認した。

- release build を実機で起動し、CLI で作った入れ子の Group・完了・着手中・未着手・未判断・取りやめ・前提待ち・Note を含む一時的な管理 root と、このリポジトリを開いて、ライトとダークの外観で三列の配置、状態ごとの色、階層の罫線、選択した行、詳細の線路・前提待ち・所属・依存元・Note・履歴の表示を画面の取得で目視した。行の選択とダークの外観は、確認用に一時的に加えたコードで切り替え、マウス・キーボードでは操作していない。
- 全幅で操作の置き場所を揃えた版では、前面に出さずに起動した確認用のアプリを幅 1180・820・400 で画面の取得で目視し、三つの幅でバーの高さと左上の操作が揃うこと、パネルの閉じるボタンがメニューのボタンと同じ位置にあることを確かめた。動きは実機では目視していない。
- 幅で列を切り替える版では、幅 820 と 400 のウィンドウで、二列、一列の一覧・詳細、パネルを画面の取得で目視した。行の選択とパネルを開いた状態は確認用の一時的なコードで作り、マウス・キーボードでは操作していない。

2026-10-07、macOS 27.0.1（Apple M6、メモリ 32 GB）、Rust 1.98.0、release build で、閲覧専用にした版（記録を変更する操作と、詳細の操作の可否の検査を取り除いた後）の大量の記録での資源使用を次のように測った。比較に挙げる 2026-10-06 の値は、macOS 27.0.1（Apple Silicon）で、合成した記録を当時のアプリ専用の保存先に置く手順で同じ形のデータを測ったもので、「対策後」は一覧が表示範囲の行だけを組み立て、詳細が操作の可否の検査を含んでいた版、「対策前」は一覧が全行を組み立て、詳細の検査ごとに記録全体から view を導出し直していた版である。

- データ: 一時的な管理 root に library で合成した 5,000 Entity（上位 Group 110 がそれぞれ Group 4 × Issue 10 を持ち、上位 Issue 50）、Note 3,300、記録 12,700 件。完了・着手中・未着手・未判断の Issue と Group 内の依存を含む。比較に同じ形の 500 Entity（上位 Group 10、記録 1,200 件）も使った。合成と純粋な導出の計時は `cargo run --release -p axon-gui --example scale -- <dir> [上位 Group 数]` で行う。`<dir>` は絶対パスで、なければ管理 root `<dir>/root` に合成し、データの保存場所 `<dir>/data` に登録してから測る。window の描画と操作の計時は、同じ `<dir>` を開いたアプリを閉じてから（計時も単一起動 lock を取るため） `AXON_GUI_SCALE_DIR=<dir> cargo test --release -p axon-gui --test scale -- --ignored --nocapture` で行い、実機では `AXON_GUI_DATA_DIR=<dir>/data cargo run --release -p axon-gui` で開く。
- 読込（保存先の読み取り・解析・view の導出、background）: 5,000 Entity で 218 ms（うち view の導出 22 ms）、500 Entity で 19 ms（同 1.3 ms）。続く board（一覧と詳細の元になる値）の導出は 8.2 ms / 0.53 ms。
- 絞り込み・検索・階層とフラットの切り替え（行の並びの導出）: 5,000 Entity で、条件ごとの中央値が 0.36〜0.60 ms（最大 0.75 ms）。
- 詳細の導出（UI thread）: 5,000 Entity で 0.37〜0.47 ms、500 Entity で 0.02〜0.07 ms。2026-10-06 の対策後の版では 23〜150 ms、対策前は 130〜310 ms だった。
- 一覧の描画: GPUI の test platform の headless window（1200×760、固定幅の文字、GPU なし）で、5,000 Entity の初期の絞り込み（3,680 行）の 1 フレームが 0.58〜0.65 ms。描画までを含めて、階層とフラットの切り替えが 1.8〜2.0 ms、状態のチェックボックスの切り替えが 3.6 ms、一覧の 31 行目の詳細を開く操作が 2.2 ms。2026-10-06 の対策後の版ではそれぞれ 0.9〜1.0 ms、2.3〜2.4 ms、4.9 ms、99 ms、対策前は 85〜89 ms、173〜175 ms、525 ms、505 ms だった。500 Entity では 1 フレーム 0.59〜0.65 ms。
- メモリ（実機の release binary の phys_footprint を `footprint` で、起動直後から約 12 秒の間に 1.5 秒ごとに取得）: 登録なしで 46〜61 MB、5,000 Entity で 77〜80 MB（`footprint` が示す起動からのピーク 112 MB）。画面を取得していないため、一覧の表示後の値かは目視していない。2026-10-06 に対策後の版で一覧の表示後として測った値（このときも画面は取得できていない）は、プロジェクトなしで 63〜67 MB、5,000 Entity で 93〜97 MB で、全行を組み立てていた対策前の binary も 94〜97 MB だったことから、増加分は表示量ではなく保持する記録と view の量に比例すると判断した。取得の方法と時点が異なるため、二つの日の値は直接比べられない。この大きさならメモリへの対策は不要と判断した。実機の描画のフレーム時間は測っていない。

2026-10-09、macOS 27.0.1（Apple M6）、Rust 1.98.0 で、本文と Note の Markdown の描画を足した版を次のように確認した。

- 大量の記録の計時（上の 2026-10-07 と同じ 5,000 Entity の合成データと手順）で、一覧の 31 行目の詳細を開く操作は、この変更の版が 3.6〜5.0 ms（計時ごとのばらつきが大きい）、変更前の版（同じ日に同じ Mac で計時）が 3.1〜3.4 ms、詳細を表示した 1 フレームはこの変更の版が 1.1〜1.3 ms、変更前の版が 1.1〜1.2 ms だった。合成データの本文は 1 件 400 byte ほどで、Note は 1〜6 件である。同じ日の計時は、2026-10-07 の値（詳細を開く操作 2.2 ms）より変更前の版でも大きく、計時した時の負荷の違いを含む。
- 実機の画面での表示と、実機のマウス・キーボードでの選択・コピー・リンクの操作は確認していない。数十 KB を超える本文や Note の詳細を開く時間も計時していない。描画の前の書き換え（構文木の解析）は、GPUI Base が 4 KB を超える本文の解析を background で行うのと違い、UI thread で行う。

起動時の復元は、次の GPUI の挙動に合わせた。

- macOS では GPUI がウィンドウの位置をディスプレイからの相対で返し、最大化を `window_bounds` で示さず、開くときの大きさを内容の大きさとして扱うことを 2026-10-09 時点の GPUI のコードで確かめ、ディスプレイの UUID、`is_maximized`、内容の大きさを保存するようにした。実機での終了と起動し直し、ウィンドウの移動・最大化・全画面、二つ目のディスプレイや外したディスプレイの上にあったウィンドウの復元は確認していない。

未確認の範囲は 2026-10-07 時点で次のとおり。

- 実機での「再読み込み」による反映。CLI を実行した後にウィンドウを前面に戻した時点で読み直されるため、実機ではボタン単独での反映を確かめていない。headless UI テストでは、再読み込みの処理で新しい記録が出ることと、ボタンで読み込み失敗が示されることを確認している。
- 実機での検索欄の日本語 IME の変換中（確定前）の絞り込みの挙動。変換と確定、確定後の絞り込みは確認した。
- 上の 2026-10-07 の利用者の確認に挙げていない、現在の版の実機の画面での表示と操作。たとえば Tab・Shift-Tab によるフォーカスの移動、空のリポジトリと絞り込みの一致ゼロ件の文言の区別、読み直し中の表示、階層の参考表示、絞り込みから外れた選択の詳細の注記、衝突中の Entity の表示と状態の絞り込みの「衝突」、構造の違反と記録にない ID の表示、ダイアログを開いている間の切り替えと記録の変更、見つからない登録先以外の読み込みの失敗（記録の破損・Git の index の unmerged）、登録の一覧を読めない・保存できない・ウィンドウの外で変わった場合の表示、ライトとダークの外観、メニューバーの編集の操作。
- `AXON_GUI_DATA_DIR` を指定しない、既定の保存場所での実機の起動。
- 実機の画面での大量の記録のスクロールとフレーム時間。
- Linux と Windows でのウィンドウ表示と入力。Linux は CI のビルドと headless テストだけを対象にする。
- macOS 15・26 と Intel Mac での起動。
