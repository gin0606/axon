# デスクトップアプリ（GPUI）

`crates/axon-gui` は GPUI で作るデスクトップアプリの crate で、binary `axon-gui` と、UI テストが使う library を持つ。CLI とは別 crate とし、CLI 単体のビルドに GPUI を要求しない。層の位置づけは [層構造の地図](architecture.md) を参照する。

## 起動と検証

workspace の `default-members` に GUI を含めないため、root の `cargo build`・`cargo run` は CLI だけを対象にする。GUI は package を指定して起動・検証する。

```sh
cargo run -p axon-gui
cargo test --locked -p axon-gui
```

実データに触れずに試すときは、環境変数 `AXON_GUI_DATA_DIR` に絶対パスを指定してデータの保存場所を置き換える（例: `AXON_GUI_DATA_DIR=/tmp/axon-try cargo run -p axon-gui`）。相対パスは起動場所に依存するため拒否する。

UI テストは GPUI の test platform 上の headless window で動き、ディスプレイや GPU を使わない。`--workspace` を付けた full verification は GUI も対象に含める。手順は [検証方針](verification.md) にある。

## 採用した依存

| crate | 指定 | 役割 |
| --- | --- | --- |
| `gpui-kit` | `=0.7.1` | GPUI、GPUI Base、GPUI Component と既定 asset の facade。アプリは GPUI を `gpui_kit` 経由で使う |
| `gpui-pre` | `gpui-kit` が `=0.3.8` に固定 | Zed の GPUI の snapshot。直接は依存しない |

版は exact 指定と `Cargo.lock` で固定し、開発ブランチや Git 依存には追従しない。更新するときは版を上げる変更として、この文書の要件と確認結果も見直す。一次資料は [GPUI Kit の導入手順](https://gpui-kit.com/docs/installation/) と [v0.7.1 の Cargo.toml](https://github.com/longbridge/gpui-kit/blob/v0.7.1/Cargo.toml)。

GPUI は serde_json の `preserve_order` を有効にするため、GUI と同じ build では CLI・コアの serde_json も挿入順の map になる。記録の canonical bytes がこれに依存しないよう、コアは記録者 metadata のキーを整列して書く（[記録 file と codec](lifecycle-file.md#記録-file-と-codec)）。

## 保存場所の規則

データの保存場所は OS のユーザーデータ領域（`dirs::data_dir()`）の下のアプリ用ディレクトリで、起動ディレクトリには依存しない。

| OS | 既定の保存場所 |
| --- | --- |
| macOS | `~/Library/Application Support/Axon` |
| Linux | `$XDG_DATA_HOME/axon`（未設定なら `~/.local/share/axon`） |
| Windows | `%APPDATA%\Axon` |

```text
<保存場所>/
    instance.lock          アプリの起動中に保持する単一起動 lock
    projects.json          プロジェクト一覧: ID・表示名・作成状態
    projects/<ID>/.axon/   各プロジェクトの保存先（CLI と同じ既存形式）
```

- プロジェクトごとに `projects/<ID>/` を管理 root とし、`axon init` と同じ初期化で `.axon/` を作る。ID は 12 桁の小文字 16 進の乱数で、日本語を含む表示名とは独立している。表示名は一覧にだけ保存し、保存先のパスに使わない。Entity ID の prefix はすべてのプロジェクトで `axon` とする。
- アプリは保存先を自分の管理 root として `Location::standalone` で開き、保存場所が Git の作業ツリー内にあっても Git を実行・参照しない。CLI から読むには `axon storage check <保存場所>/projects/<ID>` のように管理 root を指定する。
- `projects.json` は `{"format": 1, "projects": [{"id", "name", "status"}]}` の JSON で、一時 file への書き込みと rename で丸ごと置き換える。file がなく、`projects/` に `.axon/` を持つディレクトリも調べられないディレクトリもなければ、初回起動として空の一覧から始める。読めない・解釈できない・未知の `format` の一覧や、file だけが失われて保存先が残っている状態は空として扱わず、作成も含めて書き換えない。作成と再試行は、画面が保持する一覧ではなくその時点の file を読み直して変更する。名前の規則は新しく作る名前に適用し、保存済みの名前は規則が後で変わっても読み込める。
- 作成は、ディレクトリの作成 → 一覧へ `creating` で登録 → 保存先の初期化 → `ready` へ更新の順に進む。登録前に失敗すれば何も登録されず、そのまま作り直せる。一覧の置き換え後に永続化だけが失敗した場合は登録済みとしてディレクトリを残す。失敗後は一覧を読み直し、失敗が示すプロジェクトが登録されていればそれを選ぶ。一覧上は完了していても保存の永続化を確認できなかった場合は、その旨を左列に示す。登録後に失敗したプロジェクトは一覧に「作成未完了」として残り、「作成を再試行」で続きから完了できる。再試行は既存の `.axon/` を初期化し直さず、中断した初期化の残骸以外のファイルがあれば拒否する。`ready` にする前に保存先のディレクトリを永続化し、初期化の最後の同期だけが失敗した保存先も再試行で完了する。既存のディレクトリは新しいプロジェクトに再利用しない。
- `ready` のプロジェクトの保存先が見つからない・読めない場合はエラーとして表示し、空のプロジェクトとして扱わず、初期化もしない。管理 root、`.axon/` の header、記録ディレクトリのいずれかがなければ欠けた path を示して「保存先がない」とし、作り直しを促さない。他のプロジェクトへはそのまま切り替えられる。
- 単一起動 lock は OS の file lock（Unix では `flock`）で、起動から終了まで保持する。同じ保存場所で二つ目を起動すると、データを開かずに説明のウィンドウだけを表示する。異常終了すると OS が lock を解放するため、次の起動は妨げられない。

## 要件

- Rust: GUI の `rust-version` は 1.95。固定した依存の一部が 1.95 で安定化した標準ライブラリ API を使う。pull request の CI とリリース前の検証で `cargo +1.95.0 check --locked -p axon-gui --all-targets` を実行する。CLI の MSRV（`Cargo.toml` の 1.89）は GUI に合わせて上げない。
- macOS: 15 以上と Xcode Command Line Tools（GPUI Kit の要件）。
- Linux: ビルドに `gcc g++ clang libfontconfig-dev libwayland-dev libxkbcommon-x11-dev libx11-xcb-dev` を使う。CI は Ubuntu 24.04 でこれを導入し、ビルド・lint と headless の UI テストだけを行う。リンクは x86_64 Linux の Rust 既定である LLD を前提にする。window の表示には Wayland または X11 の session と Vulkan driver が要る。
- Windows: GPUI Kit は Windows 10 以上、MSVC toolchain、Visual Studio 2022 Build Tools、CMake を要件とする。

## 操作の仕様

ウィンドウの左列でプロジェクトを切り替え・作成する。切り替えはメニューから選び、作成は「＋ プロジェクトを作成」で名前欄を開いて Enter か「作成」で確定する。名前は前後の空白を除き、空、80 文字超、改行などの制御文字・行区切り・ゼロ幅や双方向制御などの書式文字、既存と同じ名前を理由付きで拒否し、入力は残す。作成中は二度目の確定を受け付けない。作成中に別のプロジェクトへ切り替えた場合は、完了後もその選択を保ち、作成が途中で止まったときは左列で知らせる。作成や再試行の失敗理由は、切り替えて戻っても作成未完了のプロジェクトに残る。中央の列の上部には選んだプロジェクトの名前、保存先の状態（読み込み中、件数、読み込み失敗と再読み込み、作成未完了と再試行）、保存先のパスを示す。起動時は一覧の先頭のプロジェクトを開く。ウィンドウの最小サイズは 880×520 で、左列・一覧・詳細（または作業欄）が横に並んだまま操作要素が収まる。

保存先の読み書きは `crates/axon-gui/src/project/` が GPUI に依存せずに担う。`ProjectConnection` は作成時に固定した管理 root にだけ `Store::read`・`Store::update` を行い、書き込みの結果を `Applied`・`NotApplied`・`PublicationUnknown` に分類する。window は disk I/O を background executor で実行し、`Requests` が発行した最新の要求の結果だけを適用するため、切り替え前に始めた遅い読み込みの結果は表示されない。

### 共通一覧と詳細

左列のプロジェクトの下に絞り込みを置く。状態（未判断・未着手・着手中・完了・取りやめ・衝突）、種類（Issue・Group）、label をチェックボックスで選び、中央の検索欄の文字列と組み合わせる。同じ項目の中の選択は OR、項目どうしと検索は AND で、ある項目の選択をすべて外すと一致はゼロ件になる。状態は実効値で判定し、保存値が未着手の Group は、直下の子の実効値が着手中か完了なら着手中になる（[Group の実効 lifecycle](../reference/lifecycle.md#group-の実効-lifecycle)）。衝突中の Entity は lifecycle を持たないため「衝突」として扱い、種類・label・検索は最初の head の値で判定する。検索は `axon list --search` と同じく、タイトルと本文に対する大文字小文字を区別する部分一致である。初期値は未判断・未着手・着手中・衝突、両方の種類、すべての label で、「絞り込みを初期値に戻す」で検索とともに戻る。絞り込みはプロジェクトを切り替えても保つ。

中央の一覧は「階層」と「フラット」を切り替えられ、初期表示は階層とする。階層では包含に沿って字下げし、兄弟は作成順に並べる。一致した Entity の祖先が一致しない場合は「参考表示」と明記して薄く表示し、件数は「N 件が一致 / 参考表示の親 M 件」のように一致件数から除く。親が記録にない Entity と包含の循環の最初の Entity は最上位に置き、各 Entity は一度だけ現れる。フラットは一致した Entity だけを作成順に並べる。各行は状態の記号とタイトル、Issue / Group・状態・状況（着手可・前提待ち・完了確認待ちなど）・label を示す。行をクリックすると詳細を開く。一覧は Tab でもフォーカスでき、フォーカスがある間は上下の矢印キーで選択を移し、選んだ行が見える位置までスクロールする。プロジェクトに Entity がない場合と、絞り込みに一致しない場合は別の文言で示し、後者には初期値に戻すボタンを出す。読み込み中と読み込み失敗の間は前回の一覧を表示しない。

右列は選んだ Entity の詳細で、所属（祖先の列）、Issue / Group・label・ID、タイトル、状態（Group の実効値が保存値と異なる場合は両方）と状況、前提待ちの理由（着手・完了の前提、止まっている Group の理由）、本文、保存された再浮上条件、子と子孫の件数、依存先、この仕事に依存している Entity、Note、履歴を示す。衝突と構造の違反があれば示す。祖先・子・依存先・依存元・前提待ちの理由に出る Entity はクリックで詳細へ移れ、記録にない ID はそのまま示す。選んだ Entity が絞り込みに一致しなくなっても詳細を閉じず、一致しないことを示す。「閉じる」で詳細を閉じると作業欄に戻る。

一覧と詳細は保存先を一度読んだ値（`crates/axon-gui/src/board/`、GPUI 非依存）から導き、表示の状況・前提・履歴はコアの `read::list`・`read::detail`・`read::history`・`read::notes` から変換する。再浮上条件のコマンドは実行せず、すべて満たしているものとして表示する。読み込みと行の導出は background executor で行い、プロジェクトを切り替えると選択を外して前のプロジェクトの結果を適用しない。同じプロジェクトの再読み込み（一覧の「再読み込み」）では、選択した Entity が残っていれば詳細を開き直す。外部での変更は自動では反映しない。

### 作業欄

詳細を開いていないとき、右列は作業欄を表示する。作業欄はタイトル入力、種類（label）を選ぶメニュー、本文の複数行入力を持つ。作業欄の入力はまだ保存しない。種類の選択肢はコアの `Label::ALL` から作り、項目名には記録と CLI と同じ綴り（`Label::name()`）をそのまま使う。メニューは項目を選ぶと閉じる。

Tab と Shift-Tab は各欄の間でフォーカスを移す。本文でも Tab は字下げではなくフォーカス移動に使い、キーボードだけで本文から抜けられるようにする。本文の字下げは `cmd-]`・`cmd-[`（macOS）で行う。ウィンドウを閉じるとアプリを終了する。macOS のメニューバーには終了と、編集（取り消す・やり直す・カット・コピー・ペースト・すべてを選択）を置く。

## 確認結果

2026-10-05、macOS 27.0.1（Apple Silicon）、Rust 1.98.0、上記の依存で次を確認した。

- `cargo run -p axon-gui` でウィンドウが開き、日本語のプレースホルダーと説明文が表示される。システムの外観（ライト・ダーク）に追従する。
- headless の UI テスト（`crates/axon-gui/tests/workbench.rs`）で、タイトルと本文への日本語入力と本文の改行、Tab・Shift-Tab によるフォーカスの一巡、メニューの選択と閉鎖、最小ウィンドウ（420×320）で全操作要素がウィンドウ内に収まることを確認した。テストの文字入力は OS の入力メソッドを経由せず、文字幅は test platform の固定幅で測るため、実際のフォントでの収まりは確かめていない。
- GUI の Rust 1.95.0 でのビルドと、CLI の Rust 1.89.0 での `cargo +1.89.0 check --locked --all-targets --all-features` が通る。
- Ubuntu 24.04（aarch64 の container、4 CPU、メモリ 7.7 GB、LLD でリンク）で上記の package を導入し、full verification の各 command が headless で通る。同じ環境で GNU ld を使うと、GUI の test binary のリンクがメモリ不足で失敗した。GitHub Actions の x86_64 runner では未実行。

2026-10-05、macOS 27.0.1（Apple Silicon）、Rust 1.98.0 でプロジェクトの保存と単一起動を次のように確認した。

- `crates/axon-gui/src/project/` の単体テストと `crates/axon-gui/tests/projects.rs` の headless UI テストで、独立した一時保存場所に日本語名のプロジェクトを二つ作り、別々の管理 root と既存形式の `.axon/` ができること、一方への書き込みが他方に現れないこと、同じ保存場所を開き直すと一覧と保存先の対応が復元されること、作成の各段階での失敗の検出と再試行、既存ディレクトリ・既存の保存先・無関係なファイルを置き換えないこと、読めない一覧・保存先をエラーとして扱い他のプロジェクトへ切り替えられること、切り替え前の遅い読み込み結果と再試行の結果を別のプロジェクトに表示しないこと、二重確定で一件だけ作ること、作成失敗時に名前を残すこと、一覧 file の喪失を初回起動と区別すること、Git の作業ツリー内の保存場所でも Git を参照しないこと、最小ウィンドウで長い名前とエラー表示があっても作業欄が収まること、メインウィンドウが単一起動 lock を保持し続けることを確認した。
- 単一起動 lock は同一 process 内の二重取得と、lock を持つ子 process を SIGKILL した後の再取得をテストで確認した。
- `/` を作業ディレクトリにして `AXON_GUI_DATA_DIR` を一時ディレクトリにした binary を起動し、lock が保持されること、二つ目の起動が lock を取らずデータを作らずに動き続けること、一つ目を SIGKILL すると lock が解放され、三つ目の起動が lock を取ることを確認した。画面の取得はできず、二つ目の説明ウィンドウとメインウィンドウの見た目は目視していない。

2026-10-05、macOS 27.0.1（Apple Silicon）、Rust 1.98.0 で共通一覧と詳細を次のように確認した。

- `crates/axon-gui/src/board/` の単体テストで、絞り込みの OR・AND、項目ごとの全解除がゼロ件になること、検索がタイトルと本文の大文字小文字を区別する部分一致であること、子の着手・完了から導く Group の実効状態での絞り込み、階層での参考表示の祖先と件数、依存・前提待ち・Note・履歴の変換、再浮上条件のコマンドを実行しないことを確認した。
- `crates/axon-gui/tests/explorer.rs` の headless UI テストで、library で一時保存場所に書いた記録を、チェックボックス・検索・階層とフラットの切り替え・初期値に戻す操作で絞り込めること、行・前提待ちの理由・所属・子のクリックで詳細を辿れること、絞り込みから外れた選択が詳細に残ること、矢印キーでの選択移動、空のプロジェクトと一致ゼロ件の区別、再読み込みで選択が残り新しい Note が出ること、読み込み失敗で前の一覧を出さないこと、プロジェクトを素早く切り替えても別のプロジェクトの記録が混ざらないこと（scheduler の seed を変えた 32 回の実行で、二つの読み込みの完了順の両方）、最小ウィンドウで長いタイトルと多数の Note があっても操作要素が収まることを確認した。
- CLI で記録を書いた一時保存場所を `AXON_GUI_DATA_DIR` で開き、実機の画面で三列の配置、階層の字下げ、状態・状況・label の表示を目視した。実機のマウス・キーボードでの操作と詳細の表示は目視していない。

未確認の範囲は次のとおり。

- 実機の画面でのプロジェクト作成・切り替え・再起動後の表示と、二重起動時の説明ウィンドウの表示。
- 実機のマウス・キーボードでの一覧と詳細の操作、詳細の見た目、検索欄での日本語 IME の変換中の絞り込み。記録が数千件ある場合の表示速度。
- プロジェクト名の欄で、日本語 IME の変換を確定する Enter が作成の確定として扱われないこと。名前の Unicode 正規化（NFC と NFD）は行わないため、見た目が同じ名前を重複として拒否できない場合がある。
- 実機での日本語 IME の変換操作（変換候補の表示位置、確定前文字列の表示、確定）と、実機のキーボード・マウスによるフォーカス移動とメニュー操作。
- Linux と Windows でのウィンドウ表示と入力。Linux は CI 相当のビルドと headless テストだけを対象にする。
- macOS 15・16 と Intel Mac での起動。
