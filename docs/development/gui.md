# デスクトップアプリ（GPUI）

`crates/axon-gui` は GPUI で作るデスクトップアプリの crate で、binary `axon-gui` と、UI テストが使う library を持つ。CLI とは別 crate とし、CLI 単体のビルドに GPUI を要求しない。層の位置づけは [層構造の地図](architecture.md) を参照する。

## 起動と検証

workspace の `default-members` に GUI を含めないため、root の `cargo build`・`cargo run` は CLI だけを対象にする。GUI は package を指定して起動・検証する。

```sh
cargo run -p axon-gui
cargo test --locked -p axon-gui
```

実データに触れずに試すときは、環境変数 `AXON_GUI_DATA_DIR` に絶対パスを指定してデータの保存場所を置き換える（例: `AXON_GUI_DATA_DIR=/tmp/axon-try cargo run -p axon-gui`）。相対パスは起動場所に依存するため拒否する。

UI テストは GPUI の test platform 上の headless window で動き、ディスプレイや GPU を使わない。`--workspace` を付けた full verification は GUI も対象に含める。手順は [検証方針](verification.md) にある。

## 採用した依存

| crate | 指定 | 役割 |
| --- | --- | --- |
| `gpui-kit` | `=0.7.1` | GPUI、GPUI Base、GPUI Component と既定 asset の facade。アプリは GPUI を `gpui_kit` 経由で使う |
| `gpui-pre` | `gpui-kit` が `=0.3.8` に固定 | Zed の GPUI の snapshot。直接は依存しない |

版は exact 指定と `Cargo.lock` で固定し、開発ブランチや Git 依存には追従しない。更新するときは版を上げる変更として、この文書の要件と確認結果も見直す。一次資料は [GPUI Kit の導入手順](https://gpui-kit.com/docs/installation/) と [v0.7.1 の Cargo.toml](https://github.com/longbridge/gpui-kit/blob/v0.7.1/Cargo.toml)。

GPUI は serde_json の `preserve_order` を有効にするため、GUI と同じ build では CLI・コアの serde_json も挿入順の map になる。記録の canonical bytes がこれに依存しないよう、コアは記録者 metadata のキーを整列して書く（[記録 file と codec](lifecycle-file.md#記録-file-と-codec)）。

## 保存場所の規則

データの保存場所は OS のユーザーデータ領域（`dirs::data_dir()`）の下のアプリ用ディレクトリで、起動ディレクトリには依存しない。

| OS | 既定の保存場所 |
| --- | --- |
| macOS | `~/Library/Application Support/Axon` |
| Linux | `$XDG_DATA_HOME/axon`（未設定なら `~/.local/share/axon`） |
| Windows | `%APPDATA%\Axon` |

```text
<保存場所>/
    instance.lock          アプリの起動中に保持する単一起動 lock
    projects.json          プロジェクト一覧: ID・表示名・作成状態
    projects/<ID>/.axon/   各プロジェクトの保存先（CLI と同じ既存形式）
```

- プロジェクトごとに `projects/<ID>/` を管理 root とし、`axon init` と同じ初期化で `.axon/` を作る。ID は 12 桁の小文字 16 進の乱数で、日本語を含む表示名とは独立している。表示名は一覧にだけ保存し、保存先のパスに使わない。Entity ID の prefix はすべてのプロジェクトで `axon` とする。
- アプリは保存先を自分の管理 root として `Location::standalone` で開き、保存場所が Git の作業ツリー内にあっても Git を実行・参照しない。CLI から読むには `axon storage check <保存場所>/projects/<ID>` のように管理 root を指定する。
- `projects.json` は `{"format": 1, "projects": [{"id", "name", "status"}]}` の JSON で、一時 file への書き込みと rename で丸ごと置き換える。file がなく、`projects/` に `.axon/` を持つディレクトリも調べられないディレクトリもなければ、初回起動として空の一覧から始める。読めない・解釈できない・未知の `format` の一覧や、file だけが失われて保存先が残っている状態は空として扱わず、作成も含めて書き換えない。作成と再試行は、画面が保持する一覧ではなくその時点の file を読み直して変更する。名前の規則は新しく作る名前に適用し、保存済みの名前は規則が後で変わっても読み込める。
- 作成は、ディレクトリの作成 → 一覧へ `creating` で登録 → 保存先の初期化 → `ready` へ更新の順に進む。登録前に失敗すれば何も登録されず、そのまま作り直せる。一覧の置き換え後に永続化だけが失敗した場合は登録済みとしてディレクトリを残す。失敗後は一覧を読み直し、失敗が示すプロジェクトが登録されていればそれを選ぶ。一覧上は完了していても保存の永続化を確認できなかった場合は、その旨を左列に示す。登録後に失敗したプロジェクトは一覧に「作成未完了」として残り、「作成を再試行」で続きから完了できる。再試行は既存の `.axon/` を初期化し直さず、中断した初期化の残骸以外のファイルがあれば拒否する。`ready` にする前に保存先のディレクトリを永続化し、初期化の最後の同期だけが失敗した保存先も再試行で完了する。既存のディレクトリは新しいプロジェクトに再利用しない。
- `ready` のプロジェクトの保存先が見つからない・読めない場合はエラーとして表示し、空のプロジェクトとして扱わず、初期化もしない。管理 root、`.axon/` の header、記録ディレクトリのいずれかがなければ欠けた path を示して「保存先がない」とし、作り直しを促さない。他のプロジェクトへはそのまま切り替えられる。
- 単一起動 lock は OS の file lock（Unix では `flock`）で、起動から終了まで保持する。同じ保存場所で二つ目を起動すると、データを開かずに説明のウィンドウだけを表示する。異常終了すると OS が lock を解放するため、次の起動は妨げられない。

## 要件

- Rust: GUI の `rust-version` は 1.95。固定した依存の一部が 1.95 で安定化した標準ライブラリ API を使う。pull request の CI とリリース前の検証で `cargo +1.95.0 check --locked -p axon-gui --all-targets` を実行する。CLI の MSRV（`Cargo.toml` の 1.89）は GUI に合わせて上げない。
- macOS: 15 以上と Xcode Command Line Tools（GPUI Kit の要件）。
- Linux: ビルドに `gcc g++ clang libfontconfig-dev libwayland-dev libxkbcommon-x11-dev libx11-xcb-dev` を使う。CI は Ubuntu 24.04 でこれを導入し、ビルド・lint と headless の UI テストだけを行う。リンクは x86_64 Linux の Rust 既定である LLD を前提にする。window の表示には Wayland または X11 の session と Vulkan driver が要る。
- Windows: GPUI Kit は Windows 10 以上、MSVC toolchain、Visual Studio 2022 Build Tools、CMake を要件とする。

## 操作の仕様

ウィンドウの左列でプロジェクトを切り替え・作成する。切り替えはメニューから選び、作成は「＋ プロジェクトを作成」で名前欄を開いて Enter か「作成」で確定する。名前は前後の空白を除き、空、80 文字超、改行などの制御文字・行区切り・ゼロ幅や双方向制御などの書式文字・ハングルの埋め字などの見えない文字（ゼロ幅非接合子・接合子 U+200C・U+200D とタグ文字 U+E0020〜U+E007F は拒否しない。これらと異体字セレクタ U+FE00〜U+FE0F・U+E0100〜U+E01EF と空白だけの名前は空として拒否する）、既存と同じ名前を理由付きで拒否し、入力は残す。作成中は二度目の確定を受け付けない。作成中に別のプロジェクトへ切り替えた場合は、完了後もその選択を保ち、作成が途中で止まったときは左列で知らせる。作成や再試行の失敗理由は、切り替えて戻っても作成未完了のプロジェクトに残る。中央の列の上部には選んだプロジェクトの名前、保存先の状態（読み込み中、件数、読み込み失敗と再読み込み、作成未完了と再試行）、保存先のパスを示す。起動時は一覧の先頭のプロジェクトを開く。ウィンドウの最小サイズは 880×520 で、左列・一覧・詳細（または作成欄）が横に並んだまま操作要素が収まる。

保存先の読み書きは `crates/axon-gui/src/project/` が GPUI に依存せずに担う。`ProjectConnection` は作成時に固定した管理 root にだけ `Store::read`・`Store::update` を行い、書き込みの結果を `Applied`・`NotApplied`・`PublicationUnknown` に分類する。window は disk I/O を background executor で実行し、`Requests` が発行した最新の要求の結果だけを適用するため、切り替え前に始めた遅い読み込みの結果は表示されない。

### 共通一覧と詳細

左列のプロジェクトの下に絞り込みを置く。状態（未判断・未着手・着手中・完了・取りやめ・衝突）、種類（Issue・Group）、label をチェックボックスで選び、中央の検索欄の文字列と組み合わせる。同じ項目の中の選択は OR、項目どうしと検索は AND で、ある項目の選択をすべて外すと一致はゼロ件になる。状態は実効値で判定し、保存値が未着手の Group は、直下の子の実効値が着手中か完了なら着手中になる（[Group の実効 lifecycle](../reference/lifecycle.md#group-の実効-lifecycle)）。衝突中の Entity は lifecycle を持たないため「衝突」として扱い、種類・label・検索は最初の head の値で判定する。検索は `axon list --search` と同じく、タイトルと本文に対する大文字小文字を区別する部分一致である。「衝突」の選択肢は、最後に読み込んだそのプロジェクトの記録に衝突中の Entity がある間だけ出す。出していない間は「衝突」を選択済みとして扱い、外したまま隠れた選択が後で起きた衝突を一覧から隠すことはない。プロジェクトを切り替えると、読み込みが終わるまで選択肢を出さず、前のプロジェクトの衝突の有無を引き継がない。このため、外していた「衝突」は切り替えで選択済みに戻る。同じプロジェクトの読み直し中と読み込み失敗の間は、前回の読み込みでの有無に従う。初期値は未判断・未着手・着手中・衝突、両方の種類、すべての label で、「絞り込みを初期値に戻す」で検索とともに戻る。絞り込みはプロジェクトを切り替えても保つ。

中央の一覧は「階層」と「フラット」を切り替えられ、初期表示は階層とする。階層では包含に沿って字下げし（字下げは 8 段までで、それより深い Entity も 8 段で示す）、兄弟は作成順に並べる。一致した Entity の祖先が一致しない場合は「参考表示」と明記して薄く表示し、件数は「N 件が一致 / 参考表示の親 M 件」のように一致件数から除く。親が記録にない Entity と包含の循環の最初の Entity は最上位に置き、各 Entity は一度だけ現れる。フラットは一致した Entity だけを作成順に並べる。各行は状態の記号とタイトル、Issue / Group・状態・状況（着手可・前提待ち・完了確認待ちなど）・label を示す。タイトルの行と種類・状態などの行は折り返さず切り詰め、すべての行を同じ高さにする。一覧は表示範囲の行だけを組み立てるため、描画の時間は記録の件数に比例しない。行をクリックすると詳細を開く。一覧は Tab でもフォーカスでき、フォーカスがある間は上下の矢印キーで選択を移し、選んだ行が見える位置までスクロールする。プロジェクトに Entity がない場合と、絞り込みに一致しない場合は別の文言で示し、後者には初期値に戻すボタンを出す。読み込み中と読み込み失敗の間は前回の一覧を表示しない。

右列は選んだ Entity の詳細で、上から Issue / Group・label・ID の行と「閉じる」、タイトル、その下の［状態を変更 ▾］［編集］と編集欄、状態（Group の実効値が保存値と異なる場合は両方）と状況、所属（祖先の列）、状態の変更の説明と結果、衝突と構造の違反（あれば）、前提待ちの理由（着手・完了の前提、止まっている Group の理由）、所属と種類の行（Group では続けて「この Group の中に作成」）、本文、保存された再浮上条件、子と子孫の件数、依存先、この仕事に依存している Entity、Note の追加欄と Note、履歴を示す。祖先・子・依存先・依存元・前提待ちの理由に出る Entity はクリックで詳細へ移れ、記録にない ID はそのまま示す。選んだ Entity が絞り込みに一致しなくなっても詳細を閉じず、一致しないことと、一致しない項目（選んでいない状態・種類・label、本文とタイトルにない検索語）を示す。「閉じる」で詳細を閉じると作成欄に戻る。

一覧と詳細は保存先を一度読んだ値（`crates/axon-gui/src/board/`、GPUI 非依存）から導き、表示の状況・前提・履歴はコアの `read::list`・`read::detail`・`read::history`・`read::notes` から変換する。再浮上条件のコマンドは実行せず、すべて満たしているものとして表示する。読み込みと行の導出は background executor で行い、プロジェクトを切り替えると選択を外して前のプロジェクトの結果を適用しない。同じプロジェクトの再読み込み（一覧の「再読み込み」）では、選択した Entity が残っていれば詳細を開き直す。変更を書き込んだ後（lock の中の拒否と結果不明を含む）の読み直しの間は、変更前の詳細を操作できない状態で残し、読み終えたら新しい記録の詳細に置き換える。詳細の中のフォーカスはそのまま残る。外部での変更は自動では反映しない。

詳細の状態メニュー・編集・移動・変換・依存解除・中への作成の可否は、一覧のために導出した view に対してコアの通常操作で検査する（`Store::prepared`）。作成・遷移・移動・依存の追加・変換は、受け入れる場合に操作後の構造の検査で記録全体を一回ずつ導出し直す。本文と label を同時に変える編集の保存前の検査は、コアの `import` がその手順ごとに導出し直す。

### 状態の変更

詳細のタイトルの下に［状態を変更 ▾］を左、［編集］を右に置き、状態の変更は控えめに強調した主操作とする。［編集］はタイトル・本文・label の編集欄を開く（[作成・編集・Note](#作成編集note)）。［状態を変更 ▾］のメニューは、Entity の種類と保存された状態から進められる遷移をすべて、採用する・着手する・完了にする・未着手に戻す・採用を撤回する・再開する・再検討する・取りやめる の順に並べ、各項目に遷移後の状態を添える。どの遷移を出すかはコアの `Operation::apply_as` が決め、Group には着手・未着手に戻すを出さない。Group の完了は「Group 全体を確認して完了にする」とし、配下の仕事が終わることとは区別する。メニューに完了の遷移を出す Group に子がある場合、配下がまだ終わっていない間は「配下の仕事がすべて終了すると、Group 全体を最終確認して完了にできます」、すべて終わって完了にできるときは成果を確認して完了にするよう、状態の下に示す。衝突している Entity は状態を持たないため、メニューを開けず、その旨を示す。

各遷移ができるかは、詳細を開いた時点の記録でコアの `Store::prepared` から得た `perform` に検査させ、アプリは独自の規則を持たない。できない遷移もメニューに残し、理由と関係する Entity のタイトルを添えて薄く示す（終了した親の配下、採用されていない祖先、完了していない依存先と祖先の依存先、終わっていない子、子が着手・完了している Group の撤回、完了した依存元がある再開など）。選ぶと書き込まずに、状態の下に理由と関係する Entity へのリンクを示す。できる遷移を選ぶと、所属・依存・種類の変更と同じく保存先の lock の中で最新の記録に対してもう一度 `perform` を行い、記録を一件書く。保存の一度に一つの実行、成功後の読み直し、lock の中の拒否、未適用と結果不明の扱い、プロジェクトの切り替え、結果の表示と消え方は所属・依存・種類の変更と同じで、結果は状態の下に出す。結果不明の反映は、読み直した記録の状態が遷移後の状態かで判断する。失敗した遷移は状態を変えたものとして表示しない。

メニューは項目を選ぶと閉じ、保存中は［状態を変更 ▾］を無効にする。選んだ入力が次の変更を起こさないように、次の入力は記録を変える操作として扱わない。

- ダブルクリックの二度目のクリック（メニューが閉じた後にその下の操作に当たるものを含む）。
- メニューを開いている間に始まったマウスの押下。メニューを閉じるだけで、その下の操作は行わない。
- キーボードで選んだ後、そのキーを離すまでの Enter・Space の繰り返し。別のキーかマウスの押下で解除する。

閉じるとフォーカスはメニューを開く前の場所（キーボードで開いた場合は［状態を変更 ▾］）に戻り、次の遷移は改めてメニューを開いて選ぶ。

### 所属・依存・種類の変更

詳細の「所属」と「種類」の行と「依存先」の欄から、選んだ Entity の構造を変える。「所属を変更」は移動先の Group を、「依存先を追加」は依存先を選ぶ欄を開く。欄はタイトルか ID の一部で絞り込め、選んだプロジェクトの記録だけを候補にする。所属の候補は Group で、自身と今の親を除く。依存先の候補は Issue・Group で、自身とすでに依存しているものを除く。一度に表示する候補は 50 件までで、残りは検索で絞り込む。候補を選ぶと変更を保存し、欄を閉じる。「所属から外す」は最上位へ移し、依存先ごとの「解除」は依存を外し、「Group に変換」・「Issue に変換」は種類を変える。Group を移動すると、中の Entity・状態・依存はそのまま一緒に移る。

変更できるかはすべてコアの通常操作（`set_parent`・`add_dependency`・`remove_dependency`・`convert`）が決め、アプリは独自の規則を持たない。所属から外す・種類の変換・依存の解除は、詳細を開いた時点の記録でコアに検査させ、できない場合はボタンを無効にして理由を示す（終了した Group の中、着手中・終了した Entity の変換、子を持つ Group の Issue への変換、完了した Entity の依存など）。同じ理由は一度だけ示す。衝突している Entity があり、どの変更もコアが拒否する間は、移動先・依存先を選ぶボタンも無効にする。候補を選んだ場合と有効なボタンを押した場合は、まず画面の記録でコアに検査させ、拒否なら書き込まずに理由を示す。受け入れられれば保存先の lock の中で最新の記録に対してもう一度同じ操作を行い、記録を一件書く。拒否の理由（自己参照、包含の循環、包含と依存を合わせた完了の前提の循環、祖先・子孫への依存、終了した Group への移動など）は日本語で示し、関係する Entity をクリックで開けるように並べる。

保存は background executor で行い、状態の変更、作成・編集・Note の追加とあわせて、すべてのプロジェクトを通して一度に一つだけ実行する。実行中は記録を変える操作をどれも受け付けないので、二度押しやキーリピートで二つ目の変更は起きない。実行中は変更している Entity のその欄に「保存中…」と示し、ほかの Entity やプロジェクトの詳細には、別の変更の保存が終わるまで操作できないことを状態の下に示す。成功すると同じプロジェクトを読み直し、一覧の階層・実効状態・状況と、詳細の所属・依存先・依存元・変更可否・履歴を新しい記録で表示する。lock の中の記録が拒否した場合（CLI などが画面の読み込み後に記録を変えた場合）は理由を示して読み直す。何も書かれなかった失敗は入力をそのままにして理由を示し、もう一度操作できる。書き込みが途中で止まり結果が分からない場合は読み直し、変更が記録に反映されているかを示す。衝突中か記録にない Entity で反映を判断できない場合はその旨を示す。自動で再送はしない。拒否・失敗・結果不明の表示は Entity ごとに保ち、その Entity の詳細を開いていれば変更した欄（所属・種類または依存先）に出す。詳細を開いていない、別の Entity を開いている、詳細を表示できない、または Entity が記録から消えた場合は、中央の列の一覧の上に、Entity へのリンクと「閉じる」とともに出す。読み込み中や読み込みに失敗している間も ID とともに出す。表示は、その Entity の詳細に表示された後に別の Entity を開くか詳細を閉じたとき、その Entity を開いたまま「再読み込み」を押したとき、「閉じる」を押したときに消える。結果不明の表示は、読み直しが成功して反映を判断するまでは「閉じる」以外では消えない。

結果が返る前にプロジェクトを切り替えた場合、結果は切り替え後の画面に出さず、その画面のために読み直しもしない。変更はもとのプロジェクトの保存先にだけ書かれる。成功した変更は戻ったときに読み直した記録に現れる。拒否・失敗・結果不明は戻ったときに一覧の上に示し、結果不明はそのときの読み込みで反映を判断する。切り替え先での操作は、もとのプロジェクトの表示を消さない。

記録者は CLI と同じく、起動時に継承した環境変数から `axon-recorder` が決める。

### 作成・編集・Note

詳細を開いていないとき、右列は作成欄を表示する。一覧の上の「＋ 作成」は詳細を閉じて作成欄のタイトルにフォーカスを移す。作成欄は作成先のプロジェクト名、タイトル、label を選ぶメニュー、本文の複数行入力、種類（Issue・Group）、状態（未判断・採用済み（未着手））、所属、「作成」を持つ。初期値は Issue・未判断・label `feat`・所属なしで、種類・状態・label は次の作成にも引き継ぐ。label の選択肢はコアの `Label::ALL` から作り、項目名には記録と CLI と同じ綴り（`Label::name()`）をそのまま使う。メニューは項目を選ぶと閉じる。Group の詳細の「この Group の中に作成」は、その Group を所属にして作成欄を開き、「＋ 作成」は所属なしに戻して開く。所属はその Group のプロジェクトを表示している間だけ使い、「外す」で所属なしに戻す。Group の中に作成できない場合（終了した Group など）は、詳細を開いた時点の記録でコアが拒否した理由を示してボタンを無効にする。作成した Entity の ID は、読み込んだ記録の Entity・Note が使っていない ID を CLI と同じ規則で作って決める。

詳細の［編集］は、詳細の中にタイトル・label・本文の編集欄を開く。「保存」は欄を開いたときの値から変えた項目だけを一つの記録で書き、変えていない項目は保存先の lock の中の最新の値のままにする。タイトル・本文だけならコアの `write`、label だけなら `set_label` と同じ記録で、両方を変えた場合は `axon import apply` と同じ単一記録の更新（`Store::import`）で、所属と依存は lock の中の最新の値を渡して変えない。この記録はアプリの履歴に「まとめて変更」と表示し、CLI の `axon log` では `axon import apply` の記録と同じ `Declaration applied` と示す。何も変えていなければ書かずに欄を閉じる。変えた項目が、欄を開いた後に読み直した記録で別の値になっていた場合は、書かずにその旨を示し、その項目だけ記録の値を新しい起点にする。もう一度「保存」すると入力した値で上書きし、変えていない項目は記録の値のままにする。完了・取りやめの Entity と、どれかの Entity が衝突している間の記録は、詳細を開いた時点でコアが編集を拒否するため［編集］を無効にして理由を示す。Note は詳細の Note 欄の「Note を書く」で開く入力欄から、どの状態の Entity にも（衝突中でも）追加できる。Note を編集・削除する操作は持たない。

作成・編集・Note の追加は、状態と構造の変更と同じく、まず画面の記録でコアに検査させ、受け入れられれば保存先の lock の中で最新の記録に対してもう一度同じ操作を行い、記録を一件書く。保存の一度に一つの実行、成功後の読み直し、lock の中の拒否、未適用と結果不明の扱い、プロジェクトの切り替え、結果の表示と消え方も同じで、結果は作成欄・編集欄・Note 欄に出す。空のタイトル、タブなどの制御文字を含むタイトル、200 文字を超えるタイトル、空白だけの Note、終了した Entity の編集はコアが拒否し、その理由を日本語で示して入力を残す。作成と Note の保存中はその欄に入力できない。作成が成功すると、作成欄の入力を空にして作成した Entity の詳細を開き、編集と Note は欄を閉じる。編集欄に保存中も入力した場合は、その入力を残して保存した値を新しい起点にする。保存中に別のプロジェクトへ切り替えた場合も作成欄を空にし、どのプロジェクトに作成したかを作成欄に示す。保存できなかったか結果不明の場合は入力を残し、もとのプロジェクトに切り替えると結果を確かめられることを作成欄に示す。結果不明の作成は、もとのプロジェクトの読み直しで判断するまで、ほかのプロジェクトの作成欄にタイトルとプロジェクト名とともに示し続け、作成欄の入力がその作成のもので、表示中のプロジェクトで作成できる状態なら、そこで作成すると入力がそのプロジェクトへの作成に使われ、保存されると空になることを添える。結果不明は読み直した記録で判断し（作成は ID の Entity があるか、編集は変えた項目が保存した値か、Note は保存を求めたときに決めた nonce の Note があるか）、判断するまで同じ欄から保存し直せず（作成はそのプロジェクトでだけできない。そのプロジェクトを読み直せない間も、ほかのプロジェクトでは作成・編集・Note の追加ができる。作成欄はプロジェクトをまたいで一つなので、ほかのプロジェクトで作成すると、残っていた入力はそのプロジェクトへの作成に使われ、成功すると空になる）、作成と Note の結果不明の表示は「閉じる」でも消せない。自動で再送はしない。

入力中の内容は記録を読んだ値とは別に、プロジェクトと Entity ごとに保つ。プロジェクトの切り替え、別の Entity を開くこと、詳細を閉じること、再読み込みで失われず、同じ Entity を開くと編集欄・Note 欄が入力したまま戻る。作成欄はプロジェクトをまたいで一つで、作成先は「作成」を押したときに表示しているプロジェクトになる。欄の「やめる」は入力を破棄する。作成欄・編集欄（値を変えたもの）・Note 欄に保存していない入力がある間は、ウィンドウを閉じる操作とメニューの終了（`cmd-q`）で確認を求め、「破棄して終了」を選んだときだけ閉じる。確認の既定の選択は「キャンセル」で、Return と Escape では閉じない。変更の保存中も同じく確認を求める。

Tab と Shift-Tab は各欄の間でフォーカスを移す。本文と Note でも Tab は字下げではなくフォーカス移動に使い、キーボードだけで欄から抜けられるようにする。本文の字下げは `cmd-]`・`cmd-[`（macOS）で行う。Enter は入力の改行や IME の確定にだけ使い、作成・保存は各ボタンで行う。タイトルは 1 行の欄のため、貼り付けた改行は取り除かれる。ウィンドウを閉じるとアプリを終了する。macOS のメニューバーには終了と、編集（取り消す・やり直す・カット・コピー・ペースト・すべてを選択）を置く。

## 既知の制約

- 固定した GPUI は macOS で、Dock のメニューなどアプリのメニュー以外から OS がアプリを終了させる操作を取り消す手段を持たないため、その終了では保存していない入力が確認なしに失われる。2026-10-06 時点で実機では確かめていない。
- 保存先の書き込み lock を別の process が持ち続けると、変更の保存はその解放を待ち続け、待つ間はすべてのプロジェクトで状態・構造の変更、作成・編集・Note の追加を受け付けない。取り消す手段は用意していない。この間にアプリのウィンドウを閉じる操作かメニューの終了を使うと、保存していない入力がなくても、変更を保存中として確認を求める。
- 移動先・依存先の候補の検査は選んだ時点で行うため、候補一覧では受け入れられるかを示さない。
- 名前の Unicode 正規化（NFC と NFD）は行わないため、見た目が同じプロジェクト名を重複として拒否できない場合がある。
