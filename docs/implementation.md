# 実装方針

## 言語: Rust

**要件**: 状態遷移の規約を型で表現し、規約違反 (実装ミス) をコンパイル時に検出できること。

この要件で **Go は落ちる**。直和型がないため C の条件
(`Always | AtDate | AfterIssue | AfterGroup`) を型で表現できず、
interface と型スイッチで代用しても網羅性チェックが効かない。
条件を 1 つ足したときの対応漏れをコンパイラが検出できない。

TypeScript は判別可能な union と `never` を使った exhaustive check で近いことはできるが、
実行時の保証がなく、branded type も型注釈を外せば通る。

Rust を選んだ理由:

| 表現したいこと | 手段 |
| --- | --- |
| A / B / C が取りうる値の限定 | `enum` |
| 条件を足したときの対応漏れ検出 | `match` の網羅性検査 |
| IssueId と GroupId を取り違えない | newtype |
| claim は着手中のときだけ | 遷移関数の引数型で制約 |
| DB から読んだ値が想定外なら落とす | `TryFrom` による境界での検査 |

`spec/axon.qnt` の sum type がそのまま Rust の `enum` に対応するため、仕様と実装の距離が近い。
最後の項目は「境界で validate、内部は信頼」の方針にあたり、
SQLite から読んだ TEXT を enum に変換する箇所を唯一の境界にできる。

**懸念**: 変更コストが高いこと。ただしモデルを先に固めてあるため、
後から変わるのは主に CLI の表層で、そこは Rust でも変更コストが低い。

## 最小スコープ

| 入れる | 落とす (後で足す) |
| --- | --- |
| issue の CRUD、A / B / C の変更 | (履歴は実装済み) |
| ready / blocked / orphaned の計算 | (blockedReason は実装済み) |
| issue 間依存 | (stale 検出は実装済み) |
| グループと階層、グループ間依存 (実装済み) | C の外部コマンド条件 (C-5) |
| 取得と着手を atomic に行う操作 | |
| actor 検出 (Claude Code / Codex) | |

### 落としたものの補足

- **履歴**: 最終的には持つ (`data-model.md` D-1)。エージェントはセッションをまたぐと
　何も覚えていないため、「なぜこの状態になったか」を追う手段が要る。
　ただし初期実装では省く。**条件は「状態更新の経路を最初から 1 箇所に集約しておく」こと** —
　更新経路が散らばっていると後から履歴を足すときに記録漏れが出る
- **blockedReason**: Quint での検査で「無いと阻害の原因が説明できない」と分かっている機能。
　ただし初期は issue 数が少なく依存も浅いので目で追える。依存が深くなってから足す
- **stale 検出**: 競合そのものは「取得と着手を atomic にする」ことで構造的に防げているため、
　残るのは「セッションが死んで着手中のまま残ったもの」の検出だけ。頻度が低いので後回し

## 現在地

最小スコープは一巡し、当初「後で足す」としたものも入っている
(履歴・`blockedReason`・stale 検出)。残っているのは実装ではなく判断のタスクで、
いずれも「まず持たずに始めて、困ったら足す」で保留にしたもの。

| 保留中の判断 | 検討材料 |
| --- | --- |
| C の条件に外部コマンドを許すか | `axes.md` C-5 |
| 優先度を相対順序で持つか | `axes.md` F-2 / F-3 |
| 表示 (pin など) を持つか | `axes.md` G-1 |

実際に使って不便を感じた時点で判断する。

## 積み残し

- **JSON 出力** — エージェント向けには簡潔なテキストで足りているため保留
- **`Condition::AfterGroup`** — 条件にグループを指定できるようにする。
　enum にバリアントを足すと未対応箇所がコンパイルエラーになるので、そこを潰せば入る
- **stale の閾値の永続化** — いまは実行時オプションのみ

## CLI の決め方

紙の上で詰めず、実装しながら決める。
コマンド名や出力は実際に打つと必ず変わるうえ、間違えてもデータ移行が要らないため。
