# Axon issue の実装

指定された 1 件の issue を、axon の状態と実装結果が一致した状態まで進める。
ユーザーによる成果物の確認を待たず、依頼された作業が完了した時点で `axon done <id>` を実行する。

## 着手

1. `axon show <id>` で本文、採否、進行、依存、グループを確認する。
2. 未着手なら `axon ready` に対象 ID があることを確認する。`axon start` 自体は ready か検査しないため、未着手・採用という表示だけで着手可能と判断しない。
3. 着手可能なら、変更を始める前に `axon start <id>` を実行する。
4. 再開を依頼され、すでに着手中なら、claim を奪ったり `axon release` したりせず、既存の申し送りと作業ツリーを確認する。安全に引き継げると判断できない場合はユーザーに確認する。
5. 未判断、不採用、依存待ち、前提喪失、終了済み、または別の作業者が着手中なら、採否や依存を独断で変えず、ユーザーに状態を報告する。
6. `axon start` が失敗したら、別の issue を選ばずユーザーに報告する。

## 実装

- issue の完了条件と関連する設計資料を読み、必要な範囲だけ変更する
- リポジトリに既存の未コミット変更があれば、依頼された作業と区別して保護する
- モデルに関わる変更では、リポジトリ指示どおり docs と spec を先に更新する
- 作業中に見つけた別件を、指定された issue に混ぜて実装しない

作業を途中で止める場合は、再開に必要な現在地、残作業、検証状況を description に残し、`axon done <id>` を実行しない。`axon write` は description の全文置換なので、既存本文を `axon show` で読み、必要な情報と申し送りの両方を含む全文を渡す。

## ドッグフーディング

axon の操作中に一般化できる摩擦を見つけたら、リポジトリ指示と [`axon-capture-issue`](../axon-capture-issue/SKILL.md) に従って未判断 issue として記録する。元の issue へ戻り、記録した改善には着手しない。

## 完了

1. issue に応じたテストを行う。Rust を変更した場合は、少なくとも次を通す。

   ```sh
   mise exec -- cargo fmt --check
   mise exec -- cargo clippy --all-targets --all-features -- -D warnings
   mise exec -- cargo test
   ```

2. 差分を読み直し、完了条件、設計、既存の未コミット変更との境界を確認する。
3. この issue に属する変更だけをコミットする。
4. 実装、検証、コミットが完了したら `axon done <id>` を実行する。
5. `axon show <id>` で終了状態を確認する。
6. ユーザーに、成果、検証結果、コミット、記録した別件、issue の最終状態を報告する。

テスト失敗や未解決の完了条件が残る場合は `axon done <id>` を実行しない。ユーザーのレビューは終了反映後に行い、レビュー結果を axon でどう扱うかはその時点のユーザーの判断に従う。
