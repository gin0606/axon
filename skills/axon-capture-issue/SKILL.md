# Axon issue を未判断で記録する

まだやると決めていない問題を、採否を先取りせず axon に残す。

## 境界

- ユーザーが未判断 issue としての記録を依頼した場合、またはリポジトリのドッグフーディング規約が記録を求める場合に使う
- 解決策を早期に固定せず、まず観測した問題を書く
- `axon decide`、`axon start`、実装は行わない
- 別の作業中に見つけた問題なら、その作業を不必要に中断しない

## 確認

1. `axon triage` と `axon list` を必要な範囲で確認する。
2. 重複の可能性がある issue だけ `axon show <id>` で読む。
3. 観測した問題と期待する挙動が実質的に同じ未終端 issue があれば、新規作成せず既存 ID を報告する。
4. 一部が重なるだけなら別の問題として記録し、関連候補を報告する。依存などの関係は合意なしに設定しない。
5. 同じ問題を扱った終了済みまたは不採用の issue があれば履歴を提示し、新規作成するか既存の判断を見直すかをユーザーに確認する。

既存 issue の書き換えや採否変更は別途合意を得る。

## 記述

タイトルは解決策ではなく問題を表す。
description から、少なくとも観測した問題と期待する挙動が読み取れるようにする。次の情報は再現や判断に必要な場合だけ加える。

- 何をしようとしていたか
- 実際に必要だった操作
- 現在の回避策

解決案がある場合は候補として分け、観測した事実と混同しない。

登録前に、先行する会話を知らない別セッションが `axon show <id>` だけを読む前提で、タイトルと description を読み直す。会話内でだけ定義した固有名詞、指示語、比較対象、暗黙の合意が残っている場合は、本文中で意味を説明するか、不要なら一般化した表現に置き換える。

## 反映

1. `axon capture <title>` を実行する。
2. 返された ID に `axon write <id> -m <description>` で説明を書く。
3. `axon show <id>` で未判断であることと文面を確認する。
4. 作成した ID と要点をユーザーに報告し、元の作業があれば戻る。

`axon capture` の成否や返された ID が不明なときは、`axon triage` や `axon list` で作成済みか確認してから再実行する。同じ内容を推測で重複登録しない。作成後の操作だけが失敗した場合は、作成済み ID と残作業を報告し、別の issue を作らない。
