Declarations describe the complete editable fields of a selected plan.

Get a plan: axon export ID... > plan.yaml
Start a new plan: axon docs declaration --example > plan.yaml

The strict YAML schema is axon-declaration/v2. The root fields are schema,
groups, issues and references. Every record has id, key, base, lifecycle,
title, description, label, parent and needs. References contain id, kind,
lifecycle and title for targets outside the edited records. Files in an
earlier schema are rejected: export existing records again, and give records
not yet in storage a label under the current schema.

Existing records have a full id and a read-only base fingerprint and lifecycle.
New records have id: null, base: null, a unique key, and lifecycle: undecided
or not-started. Keys are file-local aliases. References use { id: FULL-ID } or
{ key: local-key }. A parent must be a Group; needs lists outgoing dependencies.
Titles must not be blank. Description text is preserved without trimming.
The label is required and one of bug, feat, chore, docs, test, refactor or
spike; a new record is created with the label it declares.

Edit the declaration, then follow these steps:
  axon import prepare plan.yaml
  axon import check plan.yaml
  axon import apply plan.yaml
  axon import check plan.yaml
Prepare assigns new IDs and rewrites the file without changing storage.
Prepare prints each new record as key -> full ID.
Assigned IDs on records with base: null are kept when unused or when the
stored Entity matches the declared
final value. Prepare, Check and Apply reject a different value as a conflict:
new id already exists. It may already have been applied: export that ID into a
separate file with axon export and transfer your edits. To intentionally create
a new Entity, set id: null on the new record.
Check shows old -> new titles on one line (newlines as \n and controls escaped),
description changed/unchanged, old -> new labels, and relationship changes
without writing.
Apply validates everything, saves one stored record file per changed Entity and rewrites
the declaration; a retry finishes an interrupted save per Entity. Check again
to confirm that no differences remain. Apply also prints key -> full ID for records
whose base was null before the rewrite. An outdated base stops the whole apply.

Entities not listed in groups or issues are untouched. Removing a record from
the file does not delete or cancel it, detach it from its parent, or remove its
dependencies. To detach an Entity from a Group, write parent: null in its record.
Use needs: [] for no outgoing dependencies. Use the ordinary cancel command to
cancel work; declarations do not transition existing lifecycles.

Export never changes storage or runs resurfacing conditions. This explanation
and --example do not open storage.
