Axon concepts

An Entity is an Issue or a Group. Both share one lifecycle and one ID namespace.
Generated IDs have a management-root prefix and six random characters. A unique
suffix works wherever a command takes an Entity ID. Note IDs are complete stable
record IDs; they do not indicate priority or order.

Lifecycle
  capture -> Undecided -> accept -> NotStarted -> start -> InProgress -> complete -> Completed
  capture registers work: --kind issue|group chooses the kind, and --accept
  registers it as already adopted, in NotStarted instead of Undecided.
  withdraw returns NotStarted to Undecided; release returns InProgress to NotStarted.
  cancel terminates unfinished work; reconsider returns Cancelled to Undecided.
  reopen returns Completed to NotStarted unless a Completed dependent remains.
  Notes can be appended even after work is terminal.

A Group is never started or released. A NotStarted Group is InProgress while a direct
child is InProgress or Completed (a NotStarted child Group passes this up from its own
children); its saved lifecycle stays NotStarted until it completes.
An Issue starts only when every ancestor Group is adopted (NotStarted) and the
explicit dependencies of the Issue and of its ancestors are Completed. Completing an
Issue or Group requires the explicit dependencies of that Issue or Group itself to be
Completed and every ancestor Group to be adopted; explicit dependencies of ancestors
are not a prerequisite of its completion. Cancelled is terminal but does not satisfy
a dependency. Group completion requires all direct children to be terminal; an empty
Group completes as well. Running complete on a Group explicitly confirms final
review of the entire plan, including the outcomes and Notes of its descendants.
list, tasks and show show a Group as Empty, Confirmable, Ready, InProgress or
Blocked, and show explains a stalled Group under Stalled, including candidates
that do not surface.
parent set ID --parent G sets or moves the parent Group and parent unset ID
removes it; neither changes lifecycle.

Daily workflow
  axon capture --title 'Investigate a concern' -m 'Context and uncertainty'
  axon capture --accept --title 'Deliver an adopted outcome' -F plan.md
  axon capture --kind group --accept --title 'Deliver a plan' -F plan.md
  axon proposals
  axon tasks
  axon show ID
  axon start ID
  axon note add ID -F result.md
  axon complete ID

Reading and resurfacing
  proposals lists surfaced Undecided work. tasks lists surfaced NotStarted work and
  all InProgress work, including blocked work. Candidate conditions include every
  ancestor Group. Absence from these lists does not mean an Entity is missing.
  list includes every saved Entity by default, in creation order. --kind,
  --lifecycle, --terminal and --search narrow it without running conditions.
  list/tasks/proposals --search match only current title and description, not Notes.
  Use note search 'text' for information in Notes across all Entities, including
  Completed and Cancelled work, without running conditions. Matching is literal,
  case-sensitive, with no trimming or Unicode normalization. Empty queries are
  syntax errors; no matches produces empty stdout and a stderr hint with exit 0.
  Each Note occupies one line with complete Entity/Note IDs, local time and offset,
  and Excerpt: around the first match (24 characters before/after, full query).
  An ellipsis marks omitted text; newlines, backslashes and controls are escaped.
  Entity creation order and Note causal order are preserved. No extra filters or
  fixed-column format are provided. Read the original with note show ID NOTE_ID.
  show reads the saved text, unmet prerequisites and all Group descendants as a tree.
  Like tasks, show runs the conditions the situation of a NotStarted Entity needs: the
  ancestors, the Entity and, for a Group, its startable descendants; other Entities run
  nothing. A NotStarted Issue that does not surface is Unsurfaced. show --skip-conditions
  runs nothing and treats every condition as satisfied; use it to read saved information
  only.
  show --details includes saved conditions and all direct relationships once.
  note list ID requires an Entity ID and reads full Notes; note show ID NOTE_ID reads one stable Note. log reads state
  changes and integrations, preserving concurrent branches. --recorder-details
  includes optional stored recorder data; actor information is not ownership.

  condition set ID --command 'test -f ready.txt' stores a shell condition without
  running it. condition unset removes it. proposals/tasks/show run /bin/sh -c: 0=satisfied,
  1=unsatisfied, other exits fail the list or the display. The default timeout is 30s;
  --condition-timeout accepts positive integers with ms, s, m or h.
  --trace-conditions writes captured output to stderr. Conditions run at the
  current Git worktree root (management root outside Git). Filtering selects
  candidates before evaluating their ancestors.

Storage and recovery
  init creates a new management root: .axon/state.jsonl and nothing for Git.
  One storage format; no option selects the format or the location.
  init PREFIX sets the ID prefix: ASCII lowercase letters, digits and hyphens,
  starting and ending with a letter or digit. Without PREFIX, init lowercases the
  management root directory name and fails if that is not a valid prefix.
  Inside Git the store is untracked until you either ignore .axon/ yourself or
  follow the steps init prints to track it; do not mix the two ways in one
  repository. Init never creates or edits .gitignore, .gitattributes
  or Git config, and does not stage or commit.
  Inside Git, discovery takes the current worktree root's .axon, then the
  main worktree's .axon, so linked worktrees without one of their own use
  that store. Git replaces an ignored store without warning when you check
  out or merge a commit that tracks it. Outside Git, the nearest management
  root is used. Corrupt, unmerged or incomplete artifacts are errors; no
  fallback or automatic conversion runs.
  help, docs, actor, completion and version do not require a store.

  Preserve retained artifacts on errors. Applied, Not applied and Result unknown
  describe persistence boundaries. After an unknown result, wait for the original
  writer to finish and inspect saved state/record IDs before retrying. Creation and
  Note addition are not idempotent. Do not delete locks to bypass another writer.
  merge prepare/check/apply uses retained inputs and explicit resolution choices;
  Git driver configuration, staging and commits remain separate operations.

Use axon help <COMMAND PATH> for exact arguments. Create with --title. A title is one line of
at most 200 characters and a --reason one line of at most 500; longer or multi-line text
belongs in the description or a Note. Descriptions
accept -m/--description or -F/--file (- reads stdin). Notes use
-m/--message or -F/--file. Short flags select inline (-m) or file (-F) input;
inline long names identify the field (--description or --message). For option
values beginning with a hyphen use the equals form, for example --description='--text'.

Use axon docs declaration for plan declaration fields and the bulk-edit workflow.
Use axon docs declaration --example for a new-plan YAML template.
